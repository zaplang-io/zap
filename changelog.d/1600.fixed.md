- **`crypto.token_urlsafe` no longer leaks scratch on an entropy failure and
  raises the right exception on an allocation failure** (I#1600,
  decisions/lang/1600-token-urlsafe-scratch.md). It allocates a libc `malloc`
  scratch buffer sized by the caller; an entropy failure raised `OSError` whose
  unwind skipped the `free`, so a caller that caught and retried leaked one buffer
  per failure, and a failed scratch `malloc` raised `ValueError` rather than the
  `MemoryError` the temp-allocation policy specifies (#1581). The CSPRNG fill is
  now split into a non-raising core (`zap_crypto_fill_random_try`) and a thin
  raising wrapper; `token_urlsafe` fills through the core and `free()`s its scratch
  before raising, so the buffer is released on every path (normal return,
  `MemoryError` on allocation failure, `OSError` on entropy failure) and no partial
  token is returned. A negative `nbytes` still raises `ValueError`, and `nbytes == 0`
  still yields `""`. The other CSPRNG surfaces (`random_bytes` / `token_hex` /
  `randbelow` / `uuid.*`) keep the raising wrapper and are unchanged.
