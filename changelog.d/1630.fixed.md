- **`str.rfind` / `str.rindex` return codepoint indices** (I#1630,
  decisions/stdlib/1630-reverse-search-codepoint-index.md, superseding the
  reverse-search offset clause of D-0210). The reverse-search methods previously
  returned UTF-8 **byte offsets**, unlike `find`/`index`, `len`, indexing and
  slicing, which all speak codepoints — so on multibyte strings a successful
  `rfind`/`rindex` could return an index past the end (`"éx".rfind("x")` gave
  `2` for a length-2 string) or select the wrong character in a slice. They now
  return the last match's **codepoint index**, matching CPython: a valid position
  in `0..=len(s)`, with an empty needle returning `len(s)` and a miss returning
  `-1` (`rfind`) or raising a catchable `ValueError` (`rindex`, #1566). ASCII
  results are unchanged. `str.rpartition` still slices at the correct byte offset.
