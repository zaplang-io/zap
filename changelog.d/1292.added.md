- **A generic type can `@derive` a library trait — inferred bounds realized
  structurally (E3c)** (I#1292, epic #1289 / #1248,
  decisions/lang/1292-generic-derive-structural-bounds.md). `@derive(Trait)` on a
  generic `struct Pair[A, B]` now synthesizes `dump(self)` forwarding to the
  registered generator specialized at the type applied to its own parameters
  (`_derive_dump[Pair[A, B]](self)`); monomorphization specializes it at each
  concrete instantiation and checks the generator's per-field recursion by
  ordinary structural conformance, with the `SpecializationCache` terminating a
  recursive type. Per HQ2 (Option A, serde inferred bounds), no literal
  `[A: Trait]` bound is emitted — Zap has no `impl` construct and a method's own
  type parameter shadows the enclosing one — so the inferred bounds (which
  parameters each non-skipped field uses, with the fields' spans) are surfaced as
  data for the forthcoming derive diagnostics (E3d). Non-generic derives and
  built-in `@derive` are unchanged. A `@skip` field attribute and a recursing
  (kind-switch) generator remain follow-ups.
