- **Container repr now recurses into `tuple[T]` (and other nested-container)
  elements reliably** (I#1516). Printing a `list` / `set` / `dict` whose
  elements (or values) are a variadic `tuple[T]` rendered the elements as their
  raw buffer words instead of each tuple's `(…)` form — `print([tuple([1, 2]),
  tuple([3, 4])])` produced garbage rather than `[(1, 2), (3, 4)]`. The
  synthesized `$crepr$N` container renderer derived its name from the memo map's
  length only *after* building its (recursive) body, so a nested container's
  renderer, synthesized mid-body, observed the same pre-insert length and reused
  the same `$crepr$N` name; at link time the inner renderer then shadowed the
  outer, so the container rendered with the wrong element renderer. The name is
  now reserved in the memo map *before* the body is built, giving each nested
  renderer a distinct index. This was latent for nested `list`/`dict`/`set`
  elements too and was only masked when an earlier top-level `print` of the inner
  type pre-cached its renderer; that case is now robust as well. Indexing a
  nested element was always correct and is unchanged.
