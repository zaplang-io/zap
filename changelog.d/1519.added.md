- **A dotted decorator now resolves an imported-package function as its
  receiver** (I#1519, decisions/lang/1519-imported-decorator-receiver.md). The
  object-binding decorator from I#1509 now works across a package boundary: a
  dotted decorator whose root is an **imported module** — `import factory;
  @factory.command`, or `import factory as f; @f.command` — resolves the
  package's exported free function, reads its declared return type, and applies
  the same return-type-driven rule: a **non-void** function rebinds the
  decorated name to the returned object (so `greet.run()` type-checks), a
  **void** function still registers. A **stacked** imported chain (`@cli.command`
  / `@cli.option("--count")` / `@cli.argument("name")`) composes bottom-up into
  one nested call, keeping each decorator's typed metadata arguments. Previously
  this reported `error[ZAP3001]: unknown name 'factory'` at the decorator even
  though an ordinary `factory.command(greet)` call across the same dependency
  compiled. Local struct-receiver decorators and ordinary imported calls are
  unchanged. Unblocks zaplang-io/cli#4.
