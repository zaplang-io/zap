- **Matching an `Optional` returned by a method on a `for`-loop receiver no
  longer loses the generic enum's instance** (I#1329,
  decisions/lang/1329-for-loop-element-type-binding.md). A `match
  counter.collect()` inside `for counter in self.counters:` — where `counters`
  is a `list`-typed struct field — failed IR lowering with `error[ZAP6001]:
  cannot determine the instance of generic enum 'Optional' for this match
  pattern` even though the program type-checked, while the same call+match on a
  local receiver or a local-`list` loop worked. The monomorphizer declared a
  `for`-loop variable as `Unknown` (unlike a comprehension clause, #1131), so
  the method call on it could not be typed and its declared `Optional[Point]`
  return was lost. A single-name loop variable now binds the iterable's element
  type, so a generic call and a `match` on the loop variable infer for both
  local and struct-field iterables. A genuinely un-annotatable loop element (a
  `py` handle, an opaque iterator) still reports `ZAP6001` cleanly. The same gap
  surfacing at the type-argument site — `Optional.Some(record)` nested in a
  constructor, with `record` bound by a `list`-field loop (I#1339) — is closed
  by the same change. (A separate sema gap — struct field reads not being typed,
  #1337 — is tracked on its own.)
