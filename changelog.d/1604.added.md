- **comptime: `reflect.type_info(T)` folds in a called generic helper** (I#1604,
  epic #1248, decisions/lang/1604-comptime-reflect-in-helpers.md). A generic
  helper (not only a top-level `@derivable` generator) can now resolve
  `reflect.type_info(E)` for a type parameter `E` — including one bound to a
  container like `list[int64]` — so a kind dispatch (`if reflect.type_info(E).kind.name
  == "list"`) folds, and `reflect.type_info(E).elem` / `.key` / `.value` /
  `.inner` resolve as a **type argument** (`gen[reflect.type_info(E).elem](x)`).
  Together these let a library codec recurse into a container's element type, so
  it can handle **nested collections** of arbitrary depth (`list[list[T]]`,
  `dict[str, list[T]]`, …). Implemented by carrying the full concrete `Type` (not
  a bare name) in the comptime type substitution and resolving reflected type
  expressions in `expr_to_type`. Inert for non-generic code.
