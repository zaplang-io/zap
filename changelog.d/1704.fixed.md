- **Generic type-argument inference now reads an omitted parameter's typed
  default** (#1704). A generic function or method inferred its type arguments
  from the *supplied* call arguments and, as a fallback, the expected/return
  type, but an omitted parameter contributed nothing. So a call that relied
  entirely on a parameter's default to pin a type parameter — the no-argument
  `setting()` of `def setting[T](T value=False) -> T` — failed with `ZAP6001`
  ("cannot infer type argument 'T'"), even though `setting(value=True)` and
  `setting(value="message")` inferred `T` fine from their arguments. An omitted
  parameter whose default has a concrete type now contributes that type as the
  lowest-precedence inference source: a supplied positional or keyword argument,
  an explicit type argument, and the expected/return type all keep their normal
  precedence over it. A default the inferer cannot type statically (a call, a
  collection or constructor expression, an untyped name) contributes nothing, so
  a genuinely unconstrained type parameter is still rejected with the same
  diagnostic.
