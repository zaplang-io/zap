- **Structured fields on package-defined exceptions** (I#1432,
  decisions/lang/1432-exception-fields.md). An `@exception` struct (I#1278) now
  carries its declared fields — of any type, including non-string and `Optional`
  fields — across a `raise`/`except` boundary, including across module imports.
  A typed catch reads them as fields (`failure.error`, `failure.status`) without
  parsing the diagnostic message:

  ```zap
  @exception
  struct TokenEndpointError:
      str message
      str error
      int64 status

  try:
      raise TokenEndpointError("request refused", "invalid_client", 401)
  except TokenEndpointError as failure:
      assert failure.error == "invalid_client"
      assert failure.status == 401
  ```

  Raising such an exception constructs the real struct instance (positional and
  keyword arguments, declared defaults, and `@validate`/`@range` checks all
  apply) and attaches it to the exception as a payload the typed catch reads off.
  **Additive, non-breaking:** `except E as e` still binds `e` to the message
  string, so `str(e)`, `print(e)`, every message-only catch, catch-family
  dispatch, and the uncaught diagnostic are unchanged — `e.<field>` is the only
  new surface. A raise of an `@exception` struct with extra declared fields,
  previously rejected with ZAP6001, now succeeds. Unblocks the OAuth
  token-endpoint error payload (zaplang-io/oauth#3; RFC 6749 §5.2).
