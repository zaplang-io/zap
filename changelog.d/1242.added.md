- **`url.unquote` / `url.unquote_plus` — `errors` mode** (I#1242,
  decisions/stdlib/1242-url-unquote-errors.md). The percent decoders take an
  optional trailing `errors` str (`"replace"` | `"strict"`, default `"replace"`,
  Python `urllib.parse.unquote` parity) controlling UTF-8 handling of the decoded
  octets: `"replace"` substitutes U+FFFD for each maximal invalid subpart,
  matching CPython's `unquote(errors="replace")` / `bytes.decode("utf-8",
  "replace")` replacement counting (unblocks W3C-Baggage decoding,
  `zaplang-io/otel#4`); `"strict"` validates and raises a catchable `ValueError`
  on invalid UTF-8 (surrogates / overlong / out-of-range rejected, like
  `str(bytes)`). An unknown `errors` name raises a catchable `LookupError`. The
  default decode now yields a valid `str` (U+FFFD for invalid octets) where it
  previously built a malformed `str` from raw octets; it still never raises.
