- **`url.unquote` / `url.unquote_plus` — `errors` mode** (I#1242,
  decisions/stdlib/1242-url-unquote-errors.md, **API provisional**). The percent
  decoders take an optional trailing `errors` str (`"strict"` | `"replace"`,
  default `"strict"`) controlling UTF-8 handling of the decoded octets:
  `"strict"` validates and raises a catchable `ValueError` on invalid UTF-8
  (surrogates / overlong / out-of-range rejected, like `str(bytes)`);
  `"replace"` substitutes U+FFFD for each maximal invalid subpart, matching
  CPython's `urllib.parse.unquote(errors="replace")` /
  `bytes.decode("utf-8","replace")` replacement counting (unblocks W3C-Baggage
  decoding, `zaplang-io/otel#4`). An unknown `errors` name raises a catchable
  `LookupError`. Note: the pre-existing no-`errors` decode passed invalid octets
  through silently (producing a malformed `str`); it now raises — see the ADR
  for the default-mode decision flagged for maintainer review.
