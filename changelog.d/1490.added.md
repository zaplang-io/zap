- **`reflect.construct` zero-constructs nested-struct / `Optional` / collection /
  tuple fields** (I#1490, epic #1429, decisions/lang/1490-construct-zero-set-widening.md).
  The reflection value-construction surface (#1454) previously built a zero only
  for scalar / `str` / `bytes` fields and errored cleanly for anything else; it now
  also zero-constructs a nested struct (recursing), an `Optional[T]` (`None`), a
  `list` / `dict` / `set` (empty), and a tuple (zero per element). A struct that
  contains itself *by value* (directly or indirectly) is a clean compile error, not
  an infinite recursion; a self-reference behind an `Optional` / `list` / `dict` /
  `set` is fine. A function-typed field remains a clean "unsupported yet" error. The
  pre-existing scalar / `str` / `bytes` path is byte-for-byte unchanged. Proven
  end-to-end by the `construct_zero_set` golden. Consumed by the Json (#1470) and
  Yaml (#1484) codec shadows: a nested derived struct now round-trips through the
  **library** decoder (previously decode-via-library was deferred and the case was
  cross-checked only through the built-in decoder). `Optional` / collection codec
  decode stays deferred to the built-in codecs' own optional/collection follow-up.
