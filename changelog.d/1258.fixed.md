- **Calling a method on a module-level struct/enum constant across an import**
  (#1258). The module linker mangled a struct or enum *method* name with the
  module prefix whenever it collided with one of the declaring module's own
  top-level symbols (a free function, struct, enum, … of the same name). The
  method was then emitted under `{Struct}__{prefix}{method}` while every call
  site resolved it to `{Struct}__{method}`, so an importing module's call to
  that method was rejected during lowering with the generic `ZAP6001` (`no
  method '…' on that value`). The same module compiled standalone (its prefix is
  empty, so the mangle was a no-op). Method names are no longer prefix-mangled —
  they are resolved under their type's namespace, not as module members.
