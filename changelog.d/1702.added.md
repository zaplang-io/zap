- **`argparse` object model — options hidden from generated usage and help**
  (I#1702, decisions/lang/1702-argparse-hidden-options.md).
  `ArgumentParser.add_argument` (and the `add_argument_group` /
  `add_mutually_exclusive_group` variants) accept an optional named
  `hidden=False`. A `hidden=True` argument registers and parses *exactly* like a
  visible one — seeded defaults, typed-value validation, explicit presence
  (`has`), `required` enforcement, and mutual exclusion are all unchanged — but
  `format_help()` / `print_help()` omit it from both the usage line and the help
  rows, in root and subparser child parsers alike. A hidden positional is
  likewise dropped from usage and the `positional arguments:` section. A help
  group's heading is emitted only at its first visible member, so a group whose
  members are all hidden shows no heading and hidden members never shift the
  order of the visible rows. `-h, --help` stays visible, existing options stay
  visible by default, and a malformed explicitly-supplied hidden option or an
  unmet required hidden option still raises its usual catchable diagnostic.
  Matches Python argparse's help suppression and Click's `hidden` option
  visibility flag.
