- **Iterating a `bytes` value now works** (I#1349, decisions/lang/1349-bytes-iteration).
  `for b in data:` over a `bytes` value type-checked (under some type
  assignments) but failed in code generation with "only `for ... in range(...)`,
  … are supported by codegen yet". A `bytes` value is now iterable: a `for`
  loop, comprehension, generator expression, `*bytes` splat, or `set(...)` /
  `oset(...)` constructor yields each raw byte in order as an unsigned `int64`
  in `0..=255` (`0x00`→`0`, `0xFF`→`255`, never sign-extended negative), with
  the **byte** count as the length (empty `bytes` is zero iterations). This is
  byte-wise, not UTF-8-decoded — distinct from `str` iteration, which yields
  codepoints as `char` — and matches Python, where `for b in b"...":` binds
  integers.
