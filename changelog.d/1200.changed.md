- **Operator dispatch: parameter-aware forward/reflected fall-through** (I#1200,
  decisions/lang/1200-param-aware-fallthrough.md, epic #1189). A left type that
  defines a forward operator dunder (`__add__` …) now owns the operator only when
  that dunder's parameter accepts the right operand; when it does not, dispatch
  falls through to the right operand's reflected dunder (`__radd__` …), matching
  Python's `left.__add__` → `NotImplemented` → `right.__radd__`. This reverses the
  earlier name-level "commit" rule (I#1180): `dur + delta`, where `Duration`
  defines `__add__(self, Duration)` and `Delta` defines `__radd__(self, Duration)`,
  now reaches `Delta.__radd__` instead of erroring (or — for two same-representation
  structs — silently reinterpreting the RHS). The left still wins whenever its
  forward parameter accepts the RHS, so existing single-forward-dunder programs are
  unchanged. Generic left types resolve correctly: a concrete forward parameter is
  checked in sema, a type-variable forward parameter is checked on the monomorphized
  signature during lowering. A forward dunder whose parameter rejects the RHS with no
  matching reflected handler is a clean `ZAP4071` naming both the forward and
  reflected escape hatches.
