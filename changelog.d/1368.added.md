- **`Optional[T]` now supports `==` / `!=` and ordering (`<` `<=` `>` `>=`)**
  (I#1368). Previously only `== None` / `is None` worked and comparing two
  Optionals (or an Optional against a bare payload) bailed at lowering with
  `error[ZAP6001]: type 'Optional$T' does not define '__eq__' / '__cmp__'`, even
  though `Optional[T]` already had structural equality as a dict key / set
  element. `==` / `!=` are now structural — `None == None`, `Some(x) == Some(y)`
  iff `x == y`, and a `Some` never equals a `None` (requires `T` to support
  `==`). Ordering is a total order with **`None` before every `Some`** (the
  `Option<T>` convention: `None < Some(_)`, and `Some(x) OP Some(y)` is
  `x OP y`; requires `T` to support ordering), so a `list[Optional[T]]` is
  sortable with all `None`s first. A bare payload on the right is compared as
  `opt == Some(payload)` (`a == 7`). This deliberately diverges from CPython,
  which raises `TypeError` ordering `None` against a value — `Optional[T]` is a
  first-class type here and a total order makes it usable as an ordered key; see
  `decisions/lang/1368-optional-comparison-operators.md`. A payload type that
  does not support the operator still produces the same clean diagnostic a direct
  comparison would.
