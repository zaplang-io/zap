- **A generic `match` arm that is impossible at a given specialization no longer
  crashes native codegen** (I#1326, decisions/lang/1326-dead-match-arm-elision.md).
  A generic function that destructured a nominal struct through an `as` binding
  in a `match` arm and then read that binding's fields — e.g. `case Date() as
  day:` feeding `datetime.combine(day, …)` — panicked the LLVM backend when
  instantiated with a scalar (`promote(1)`): the arm's constant-false branch was
  still lowered, emitting a struct `FieldGet` that read fields off an `i64`
  (inkwell: `Found IntValue … expected PointerValue`). Such a statically-dead arm
  is now elided before its body is lowered, so the invalid field reads are never
  emitted; the specialization routes straight to its fallback arm (e.g. raising
  `TypeError`). Specializations where the arm *is* reachable keep the nominal
  pattern binding and the arm unchanged. The elision is the general form of the
  tuple-shape check the lowerer already applied, now covering struct, tuple,
  sequence, `as`, and or-patterns. Surfaced after #1310 unblocked native
  inference (zaplang-io/datetime-utils#22).
