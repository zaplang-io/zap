- **A generic method's bound type parameters now flow into its return type**
  (I#1643, decisions/lang/1643-generic-method-return-binding.md). When a generic
  method call binds its type parameters from the arguments, the binding now
  substitutes into the result type instead of erasing to `Unknown` — mirroring
  #1623 for free functions: with `struct Opt: def make[T](self, Type[T] kind, T
  default) -> T`, `int64 n = o.make(int64, 1)` compiles and `str s = o.make(int64,
  1)` is now rejected (the result is `int64`, not `str`). The substituted type is
  used only when the method is generic and the binding produced a concrete type, so
  a non-generic method result and a generic method whose return did not bind stay
  loose — preserving the method-chain operator typing that drives `&`/`|`/`~`
  dispatch off the returned struct. Numeric widening still compiles.
