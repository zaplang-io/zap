- **A returning dotted decorator now binds the decorated name to its object**
  (I#1509, decisions/lang/1509-decorator-binds-object.md). A dotted function
  decorator `@recv.method(...)` whose receiver method has a non-void return
  type now *rebinds* the decorated name to the object that method returns
  (Click-style command objects), keeping the original function, renamed
  `<name>$impl`, as the typed callable the method receives — where it previously
  registered-and-discarded the return, leaving the name the raw function so
  `greet.run()` failed `error[ZAP6001]: method call on a non-struct value`. The
  decision is return-type-driven: a **void** method is unchanged and still
  registers (fastzap `@app.get(...)`). Stacked `@command` / `@option` /
  `@argument` decorators compose bottom-up into one nested call, retaining the
  option/argument arguments as metadata for a later dispatcher. A receiver whose
  type the pre-sema desugar cannot resolve (including an imported-module
  receiver — the zaplang-io/cli#4 extension) falls back to registering, so no
  existing program changes behavior.
