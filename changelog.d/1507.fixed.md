- **`argparse.ArgumentParser` now honors the `--` end-of-options separator and
  rejects malformed option inputs** (I#1507, I#1508), matching Python's
  `argparse.ArgumentParser.parse_args`. A `--` token is consumed and ends option
  parsing: every remaining token fills a declared positional literally (dashed
  filenames, a literal `--help`, even a literal `--`), while ordinary
  missing/extra-positional checks still apply — previously `--` was sent through
  option lookup and raised `unrecognized arguments: --`, never binding the
  positional. A value-taking option is no longer satisfied by a following
  option-like token (`--name --verbose` now raises `expected one argument`
  instead of consuming `--verbose` as the value; this holds for both known and
  unknown following options), and a zero-arity flag rejects an attached value
  (`--verbose=false`, and the same for `store_false` and an empty `--verbose=`,
  now raise instead of silently storing the flag). Explicit attached values
  (`--name=--verbose`, `--name=`), negative-integer values (`--count -3`) and a
  bare `-` value continue to parse.
