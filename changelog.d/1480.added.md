- **E4 dogfood: the `@derive(Csv)` codec shadow-proved over the `@derivable`
  mechanism** (I#1480, epic #1429, decisions/lang/1480-csv-codec-shadow.md). Two
  library `@derivable` generators express a CSV encode (`to_csvcodec`) and decode
  (`from_csvcodec(str) -> Self`) in pure Zap source — CSV has no source-accessible
  DOM or module (unlike Json #1470), so the shadow uses only string primitives
  (`str()`, `.split`, `",".join`, `int()` / `float()`, a manual bool parse) plus
  the E4 enablers `reflect.construct` / `reflect.set_field` (#1454) and
  derived-method `Self`-return typing (#1455). A behavior-identical golden proves
  they agree with the built-in `@derive(Csv)` by round-trip, cross-checked in both
  directions, covering int64 / str / bool / float64. Shadow proof only — the
  built-in Csv codegen, `DERIVABLE_TRAITS` and the prelude are left untouched.
