- **Merge-queue failures are now surfaced on the PR** (I#1268,
  decisions/tooling/1268-merge-queue-failure-reporting.md). The full
  LLVM/aarch64/Windows matrix runs only on the `merge_group` candidate, so its
  results attach to the ephemeral queue ref and never to the PR. A new
  `merge-queue-report` CI job turns a genuine queue failure or cancellation into
  a sticky PR comment (naming the failed job(s) and linking the run), so a
  comment present means the PR failed in the queue and its absence after an
  eviction means a non-failure reason (the base moved, or a PR ahead failed). A
  read-only `scripts/mq-status.sh <pr>` helper prints the same per-job
  conclusions on demand from the terminal. No change to the fast `pull_request`
  gate — the full matrix is **not** re-added there.
