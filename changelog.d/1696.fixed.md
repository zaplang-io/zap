- **`@derive(Json)` decode now handles an `Optional[T]` field of any element
  payload** (I#1696, decisions/lang/1696-json-optional-decode-payloads.md). The
  prelude library decoder used to accept only `Optional[int64]` /
  `Optional[str]` and rejected every other payload with `@derive(Json):
  unsupported Optional payload` — which blocked **274 of 435** generated AWS SDK
  clients, whose shapes routinely carry an Optional field of a `float64`, `bool`,
  `list`, nested `@derive(Json)` struct, or open string `enum`. Decode is now
  symmetric with encode: a present value recurses into the payload through the
  shared element codec and wraps it in `Some`, while an absent key or an explicit
  JSON `null` stays `None`. A `bytes` / `DateTime` payload (bespoke top-level
  codecs the element codec does not reach) and a nested `Optional` payload remain
  a clean `unsupported Optional payload` reject, as on encode.
