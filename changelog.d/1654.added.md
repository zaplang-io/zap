- **`int8` / `int16` — first-class signed narrow-integer scalar value types**
  (I#1654, decisions/lang/1654-fixed-width-integer-semantics.md, epic #1644).
  The signed mirrors of `uint8`/`uint16`, completing the signed integer family
  below `int32`. They previously existed only as array `Dtype`s, so a scalar
  annotation `int8 x` resolved to an unknown type; they are now reserved type
  keywords (with the short `i8`/`i16` spellings) usable anywhere a scalar type
  is — variable / field / parameter / return annotations, `dict`/`set` keys and
  values, `list` elements, generic bindings, struct fields, Display, reflection,
  and the C-FFI boundary. The `int8(x)` / `int16(x)` value conversions wrap with
  C-cast semantics (`int8(300) == 44`). They inherit the locked width-stable
  arithmetic model: a fixed-width result keeps its width and wraps
  (two's-complement), an untyped literal infers to the context type and **must
  fit** (`int8 x = 300` is a compile error, `ZAP4016`; use `int8(300)` to wrap),
  implicit widening runs up the signed tower (`int8`→`int16`→`int32`→`int64`),
  narrowing stays an explicit cast, and signed↔unsigned mixing remains a compile
  error (`ZAP4015`). A handler parameter of either type now binds from the
  argparse `Namespace` (`int8 n` → `int8(ns.get_int("n"))`), closing the #1644
  wide-scalar piece for them. Python has a single unbounded `int`; these
  fixed-width scalars are a Zap extension (cf. Rust `i8`/`i16`, NumPy NEP 50).
