- **E4 dogfood: `@derive(Repr)` shadow-proved; `reflect.type_info(T).name` folds
  as a value** (I#1430, epic #1429, decisions/lang/1430-derive-repr-shadow-prove.md).
  Monomorphization now folds `reflect.type_info(T).name` to the concrete type's
  name (a string literal) when used as an ordinary value — previously it resolved
  only as a `comptime for` iterator or a kind-dispatch condition, so a generator
  that named its type reached lowering as an unresolved `reflect`. With that and
  the `repr()` builtin (#1384), a library `@derivable` generator now expresses the
  built-in `Repr`'s `TypeName(field=value, …)` form, and a behavior-identical
  golden shows the library shadow and the built-in `repr()` produce the same
  string for int / str / bool fields and a nested derived struct. Shadow proof
  only — the built-in `Repr` and the default renderer are left untouched.
