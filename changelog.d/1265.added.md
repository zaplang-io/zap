- **A bare value of type `T` now widens to `Optional[T]` in every position**
  (I#1265, decisions/lang/1265-optional-implicit-widening.md). A concrete `T` is
  accepted where an `Optional[T]` is expected and is implicitly wrapped as
  `Some(T)` — in a `return`, an `Optional[T]` parameter, a typed binding, a
  list-literal element, and the constructor/assignment/`.append` positions that
  already worked — matching Python's `x: Optional[int] = 1` and completing the
  bare-`None` widening. Previously only a bare `None` (and an explicit
  `Optional.Some(...)`) widened everywhere while a bare payload was a type error
  outside a struct-constructor field (`def f() -> Optional[int64]: return 1` was
  `error[ZAP4003]`; `Optional[int64] x = 1` and `list[Optional[int64]] xs =
  [1, 2]` were `ZAP4001`; passing `1` to an `Optional[int64]` parameter was
  `ZAP4021`). This resolves the design question deferred by I#1262 (widen
  everywhere, not reject); the tagged-`Some` IR wrap is I#1262's.
