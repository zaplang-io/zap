- **`zap test` now resolves imports from the project `zenv` and sibling source
  modules** (I#1232, decisions/tooling/1232-zap-test-module-resolution.md). A
  `@test` can import a dependency installed in the project `zenv`
  (`zap add --path` or a registry), a sibling module in the same project, and
  use their qualified exception types (`raise`/`except <dep>.SomeError`) — the
  test harness now runs the same whole-program module resolution as
  `zap run`/`zap build` (SPEC §16, D-0054) instead of type-checking the single
  entry file in isolation. Before this, every such import failed at sema with
  `error[ZAP3001]: unknown name '<dep>'`, which blocked the native-test
  convention (`zap test tests/`) used by all official non-core packages. A
  genuinely unresolved import now reports the linker's `ZAP3010` (module not
  found) and an unknown name still reports `ZAP3001`; test discovery and
  reporting are unchanged.
