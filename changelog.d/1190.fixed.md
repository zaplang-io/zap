- **A generator expression passed to a generic constructor is rejected again,
  not monomorphized over a synthetic iterator type** (I#1190, follow-up to
  I#1167 / epic I#1169). The sema-driven type backfill added in I#1167 bridged
  sema's internal, `$`-prefixed synthetic iterator types into monomorphization,
  so `Optional.Some((x for x in xs))` monomorphized a bogus `Optional$$genexpr`
  instance (and a generator-function call `Optional.Some(gen())` an
  `Optional$$gen:<name>` one) instead of failing closed with `ZAP6001`
  ("cannot infer type argument 'T'"). `Ty::to_ast_type` now returns `None` for
  any `Named` type whose name begins with the synthetic sigil `$`, so these
  unspellable, element-erased types never reach the monomorphizer — restoring
  the pre-I#1167 fail-closed boundary for generators (I#596). The I#1167
  inference wins (module constants, built-in call returns, subscript / slice /
  tuple / comprehension) are unaffected.
