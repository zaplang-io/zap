- **Generic-interface conformance is now enforced at value positions** (I#1428,
  decisions/lang/1428-iface-value-position-conformance.md). A parameter, return,
  or typed binding annotated `SomeIface[Arg]` now checks structural conformance
  against the real instantiation — a new sema type `Ty::Iface(name, args)` carries
  the type arguments that the old `Ty::Named` dropped at resolution. So a struct
  that conforms at the right instantiation (`IntBox` → `Container[int64]`) is
  accepted at an argument / return / variable position, while a wrong
  instantiation (`Container[str]`) is rejected with a diagnostic naming the method
  and the instantiation. This affects every generic interface (the #1205 family)
  and unblocks the element-type-carrying `iter`/`next` (#1382) and `map`/`filter`
  (#1390) work. Interface values still erase to the same `{data, itable}` fat
  pointer, so codegen is unchanged.
