- **Struct constructor arity and unknown field names are now checked in sema**
  (I#1467, follow-up to #1464). Passing more positional arguments than a struct
  has fields (`P(1, 2, 3)` for a two-field `P`) is now `error[ZAP4062]`, and a
  named argument that matches no field (`P(bogus=1)`) is `error[ZAP4063]`, at
  type-check time (through `zap check` / the MCP `check_source` tool / the LSP) —
  bringing struct construction to parity with enum-variant construction. These
  were previously caught only in IR lowering (too-many as `ZAP6001`) or not
  reliably at all, so no program's accepted/rejected status changes; the
  diagnostics just move earlier. Omitting an **undefaulted** field is still
  accepted — the language permits constructing with a field unset and assigning it
  later (e.g. a `@scoped` owner that fills its field in `__enter__`), so
  missing-required-field enforcement is a separate design decision left open on
  #1467.
