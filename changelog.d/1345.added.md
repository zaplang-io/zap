- **`datetime.zone_abbreviation(dt) -> Optional[str]`** (I#1345,
  decisions/stdlib/1345-zone-abbreviation.md) — the IANA zone abbreviation of
  `dt`'s retained named zone at its instant (e.g. `Some("EDT")` / `Some("EST")`
  across the `America/New_York` fall-back overlap, `Some("CET")` / `Some("CEST")`
  for a European zone). The result is determined by the UTC instant, so it is the
  same whether `dt` came from `datetime.resolve(…, fold=)` or from converting from
  UTC. Abbreviations are faithful to the bundled tz database, matching CPython
  `zoneinfo.tzname()` — including numeric forms such as `-04` / `+0530` and `LMT`
  for pre-standard intervals. A naive, fixed-offset, or unknown-zone value carries
  no named zone and returns `None`. This is an additive accessor: `strftime`'s
  `%Z` still renders the numeric offset (`UTC-04:00`) unchanged. The bundled tz
  tables now carry a per-transition abbreviation (a compact index into a shared
  string pool; the transition array does not grow). Unblocks the non-core
  datetime-utils `parse(tzinfos=…)` abbreviation resolution.
