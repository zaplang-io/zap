- **Enum instance-method calls now type-check their arguments** (I#1642,
  decisions/lang/1642-enum-method-argcheck.md). An enum method call `c.method(...)`
  was previously typed through a fully loose receiver path with no argument check
  at all, so a plain mismatch compiled and a generic method monomorphized the
  wrong type: `enum Color: def plain(self, int64 n)` accepted `c.plain("not an
  int")`, and `def take[T](self, T x, T y)` lowered `c.take(1, "hello")` with a
  string in an `i64` slot. The enum call path now resolves the method from
  `EnumInfo.methods` and checks each argument (`coercible`, with `self` dropped so
  positions line up) and generic type-parameter consistency, both `error[ZAP4021]`
  — completing the enum follow-up #1622 deferred. Consistent calls and numeric
  widening still compile, and arity stays loose. (Struct instance methods still
  leave a plain argument mismatch unchecked — a tracked follow-up.)
