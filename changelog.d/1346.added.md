- **Comptime reflection: nested types carry a use-site source span**
  (I#1346, decisions/lang/1346-nested-type-use-site-span.md). A nested type
  reached through the reflect model — `field.ty.elem`, `.key`, `.value`,
  `.inner`, and tuple `.elems[i]` — now exposes `.span`, the span of that type
  *as written in the field's declaration* (the `Widget` in `list[Widget] items`,
  not a declaration of `Widget` elsewhere). It composes to any depth
  (`list[list[Widget]].elem.elem.span`, `dict[str, list[Widget]].value.elem.span`).
  A `@derivable` generator can now reject a nested level with
  `comptime.error(f.ty.elem.span, …)` and the compiler underlines exactly that
  element, while the `required because of …` frame still attributes to the
  enclosing field. A reference with no declared type in hand (a top-level
  `reflect.type_info(T)`) has no use-site and `.span` is a clean comptime error.
  This is the enabler the multi-level derive `required because of` chain
  (E3d, I#1293) was waiting on.
