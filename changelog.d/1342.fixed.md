- **`Optional.None` now infers its type as a call argument and a struct-
  constructor field** (I#1342, decisions/lang/1342-optional-none-arg-field-inference.md).
  `take(Optional.None)` and `Box(Optional.None)` failed IR lowering with
  `error[ZAP6001]: cannot infer type argument 'T' of generic 'Optional'` even
  though the parameter / field declared the exact `Optional[...]` instance,
  because the monomorphizer rewrote every call argument with no expected type —
  while the same `Optional.None` already inferred in `return` position and in a
  type-annotated binding, and bare `None` worked everywhere. A non-generic
  callee's argument is now rewritten with the callee's declared parameter / field
  type as its expected type (by position or keyword), so a payload-less generic-
  enum variant (including a user enum's, e.g. `Maybe.Nothing`) pins its type
  argument there. `Optional.Some(...)`, generic callees, methods, and
  variadic/spread positions are unchanged, and a bare `Optional.None` with no
  expected type (e.g. `auto x = Optional.None`) still reports `ZAP6001`.
