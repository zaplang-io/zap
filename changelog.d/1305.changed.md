- **CI runs the end-to-end `.zap` suites on the runner's cores instead of a fixed
  width of 2** (I#1305, decisions/tooling/1305-widen-e2e-pool-in-ci.md). The
  golden, conformance and CPython-differential corpora now share one harness
  (`crates/driver/tests/common/mod.rs`) with a two-pass bounded pool: ordinary
  fixtures run wide at `ZAP_GOLDEN_JOBS` (the `full`/`arm64` legs export
  `$(nproc)`) while the concurrency/GC/scheduler-sensitive subset — anything under
  `tests/race/`, any `stress`/`preempt` fixture, or one carrying a `.serial`
  sidecar — stays at the conservative `ZAP_GOLDEN_SENSITIVE_JOBS` default
  (`min(2, wide)`). Local `cargo test` is unchanged (both passes default to width
  2). The conformance and diff suites also adopt the `#1113` compile/run deadline
  split so widening them can't misreport linker starvation as a program hang.
  Developer/CI-only; no language, library or runtime behavior change.
