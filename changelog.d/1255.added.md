- **Comptime build-time-cost controls — `type_info` memoization + specialization
  dedup + compile-time metric (E2)** (I#1255, epic #1249,
  decisions/lang/1255-comptime-memoization.md). The `TypeRegistry` now memoizes
  each type's reflection record (keyed by a faithful canonical type key, so
  `Optional[int64]` and `Optional[str]` never collide): `type_info(T)` is
  computed once and reused on every later introspection, across the container-
  recursion and `field.ty` paths. `MemoStats { computed, reused }` exposes the
  accounting. A `SpecializationCache` models mono's `#671` global-recv dedup for
  the comptime generator layer — a `(type, backend)` specialization is recorded
  once, lazily, per used pair (not per call-site), distinct backends distinct.
  The memo stats on a reflection-heavy program are a deterministic, comparable
  compile-time metric (a lost-memo regression fails the host test, no LLVM, no
  timing flakiness) — the CI regression signal. Compiler-internal and
  host-tested; on-disk caching and a wall-time CI bench job are deferred; no
  behavior change for existing programs.
