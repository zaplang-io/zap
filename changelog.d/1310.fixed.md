- **`zap test` keeps sema's inference for a generic reflected operator over a
  built-in result** (I#1310, decisions/lang/1308-test-harness-threads-sema-types.md).
  A `@test` body whose generic reflected operator infers its type argument from a
  built-in or stdlib-seam result — `len(xs) + Delta(1)`, or `date + Delta(1)`
  with a `__radd__[T]` — failed native test lowering with `error[ZAP6001]: cannot
  infer type argument 'T' of operator method '__radd__'`, though `zap ir`
  compiled the same body. The native runner discarded the sema `TypeMap` and
  lowered the harness with `TypeMap::default()`, so inference fell back to the
  pre-#1167 path and lost the result type; the harness now lowers with sema's
  types, so reflected `+`/`-` over core Date and DateTime inputs (and built-in
  results) work under `zap test` as they do under `zap run`. Same one-line fix as
  I#1308.
