- **A `match` arm made unreachable by a preceding irrefutable arm is now elided
  before lowering** (I#1668,
  decisions/lang/1668-irrefutable-arm-specialization.md). A generic that
  dispatches on its own type parameter — `match previous: case Command() as
  composed: ... case _: fn(..) handler = previous` — used to fail to compile for
  the `Inner = Command` specialization with `ZAP4001: value of type Command is
  not a function, but fn(Context, Namespace) -> void is expected`, because the
  unreachable `case _:` body was still lowered against a `Command`. An unguarded
  arm whose pattern is statically irrefutable for the scrutinee type (a wildcard
  or capture, a nominal struct `S()`/tuple pattern against exactly that type with
  irrefutable fields, an `as`/or-pattern over one) is now treated as a catch-all,
  and every later arm is dropped before its body is lowered — the dual of the
  statically-dead arm elision of #1326, and behaviour-preserving since an arm
  after an unconditional match never runs. One generic body now serves both the
  composed-object and callable specializations (unblocking the normalization step
  of zaplang-io/cli#4). A guard, a refutable field test (`S(n=0)`), a literal, a
  sequence pattern, and an enum-variant pattern are not irrefutable, so their
  following arms stay live.
