- **Typed `FileNotFoundError` / `OSError` from filesystem reads** (I#1311,
  decisions/lang/1311-filesystem-notfound-error.md). `fs.read_file` and
  `fs.read_bytes` now raise a **`FileNotFoundError`** when the path does not
  exist (`open(2)` → `ENOENT`) and a generic **`OSError`** for every other
  failure (permission denied, a directory where a file was expected, any other
  I/O error, or a post-open read error), instead of a single untyped
  `Exception`. Both are new first-class built-in exception types — mirroring
  CPython's `FileNotFoundError` ⊂ `OSError` ⊂ `Exception` — so `except
  FileNotFoundError` selects only the missing-path case, `except OSError`
  catches the whole filesystem-error family, and an existing `except Exception`
  still catches every read failure unchanged. A caller can now fall back to
  defaults for an absent file (e.g. a missing `resolv.conf`) without racing a
  prior `fs.exists` check or parsing a localized error message. The error
  message text is unchanged. (Mutating / metadata fs calls still raise the
  generic error; a consistency follow-up is tracked separately.)
