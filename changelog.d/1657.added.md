- **`bigint(str)` and `complex(str)` parse strings** (I#1657,
  decisions/lang/1657-str-parse-conversions.md). `bigint("123…")` parses an
  arbitrary-precision integer (optional sign, `0x`/`0o`/`0b` radix prefix and `_`
  separators, beyond the `int64` range `int(str)` is limited to) and
  `complex("1+2j")` parses a Python-style complex literal (`re`, `im j`, or
  `re +/- im j`, with optional whitespace and one layer of parentheses), matching
  CPython. A malformed string raises a catchable `ValueError`, exactly like
  `int(str)` / `float(str)`; a string is valid only as `complex`'s sole argument
  (`complex(real, imag)` stays numeric). This unblocks the deferred
  `Namespace.get_bigint` / `get_complex` getters (#1655, epic #1644).
