- **A nested collection display with a leading empty element now infers its
  element type from a non-empty sibling** (#1708). An un-annotated
  `[[], ["group", "switch"]]` was accepted by the type checker (which joins the
  siblings to `list[list[str]]`) but then rejected at lowering with
  `error[ZAP6001]: list element expects i64, found ptr`: lowering read the
  element kind off the *first* element, and a leading empty `[]` defaults to
  `list[int64]`, so the `list[str]` sibling no longer fit. Lowering now consults
  the type sema already inferred for the display (the #1167 inferred-type map)
  when its first element gives no usable element type, so it agrees with sema
  instead of accepting the expression and failing to store a sibling. The empty
  member is covered both before and after a non-empty sibling, at any nesting
  depth, and the same gap in a dict **value** position (`{1: [], 2: ["x"]}`) is
  fixed. Scalar-element displays (`[1, 2, 3]`) are unaffected — their first
  element is already a usable anchor, so their lowering is unchanged.
