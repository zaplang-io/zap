- **Coroutine-local execution context — `ContextVar[T]` / `ContextToken`**
  (I#1237, decisions/lang/1237-coroutine-local-context.md; **PROVISIONAL**).
  Zap's analogue of Python `contextvars`: `cv = ContextVar[T]("name")` (or
  `ContextVar[T]("name", default=d)`) binds a typed value on the *current*
  coroutine with `tok = cv.set(v)`, reads it from any deep callee with `cv.get()`
  (no parameter threading), and restores the previous value with `cv.reset(tok)`.
  The binding lives on the coroutine, so it survives scheduler suspension/resume
  and worker migration, and two interleaved coroutines on one worker stay
  isolated. A `spawn`ed child inherits a **snapshot** of the parent's context at
  spawn time (Python `copy_context`); the child's own `set` never leaks back to
  the parent or siblings. `get()` returns the construction default when unbound,
  or raises a catchable `LookupError` when there is none. This resolves the
  "Coroutine-local storage" open question in `design/0005-concurrency.md` and
  unblocks the OpenTelemetry current-span API (zaplang-io/otel#2). v1 supports a
  reference value type or `int64`; other scalar and by-value aggregate value
  types are a follow-up. The API shape and inheritance/restore semantics are
  provisional pending final review.
- **Built-in nominal type-name keywords are accepted as member/method names**
  (I#1237). A `.name` member position is unambiguous, so `set`, `list`, `str`,
  and the other built-in type keywords may now be used there — e.g.
  `ContextVar.set(...)`, matching Python — where they previously failed to parse.
