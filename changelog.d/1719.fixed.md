- **Complex `@` / `dot` no longer silently corrupts; it is rejected cleanly** (I#1719).
  `a @ b` / `dot(a, b)` on a `complex` array — or any complex↔real mix — used to
  mis-route to the **integer** matmul kernel: a complex element is a 16-byte `(re, im)`
  pointer-word, which `zap_array_doti` / `zap_matmul_i` read and wrote as a raw `int64`,
  producing silent garbage and memory corruption with no error. `lower_array_matmul` now
  rejects complex operands at compile time — exactly as `sort`/`argsort`/`unique` already
  reject complex — across every form (1-D·1-D, 1-D·2-D, 2-D·1-D, 2-D·2-D, both the `@`
  operator and the `dot()` builtin, and complex@complex / complex@real / real@complex). A
  real complex matmul kernel is deferred to the complex-array work (I#938).
