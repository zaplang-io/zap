- **A null (non-`Optional`) reference field read or store now raises a
  catchable, located `NullReferenceError` instead of crashing** (I#1493, Epic
  I#1489, decisions/lang/1489-null-reference-error.md). Reading or assigning a
  field through a reference that is null — e.g. a non-`Optional` reference field
  left unset at construction, then used — previously terminated the process with
  an uncatchable `SIGSEGV` (and a bare field read raised a generic `TypeError`
  "member access on None"). It now raises `NullReferenceError` (#1492), which
  `except NullReferenceError` and `except Exception` both catch and an unrelated
  clause does not, with a located message naming the field, its owning type, and
  the source location, e.g. `null dereference reading field 'name' of 'Node' at
  foo.zap:7` (writing on a store). The check is an explicit null test lowered to
  a raising call (the locked explicit-check-primary mechanism, portable to every
  target); `Optional[T]` access is unchanged and keeps its own `None`/unwrap
  path. This is the first increment of the #1489 guarantee (field read/store);
  the remaining deref sites — method-call receiver, index base, for-iteration
  base, and built-in reference *values* such as `len(n.name)` on a null `str` —
  follow in subsequent #1489 sub-PRs.
