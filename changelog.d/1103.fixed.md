- **Index-overload dunders now type-check their index/value argument** (I#1103,
  D-0047). `a[i]` / `a[i] = v` on a struct with `__getitem__` / `__setitem__` used
  to form the call without checking the supplied argument against the dunder's
  declared parameter type, so a mismatched index (e.g. `b[5]` where the key type
  is `str`) compiled and lowered an `i64` straight into a pointer (key) slot — a
  latent type confusion. The index argument (and, for `__setitem__`, the value
  argument) is now checked, raising `ZAP4021` exactly as a normal argument/
  parameter mismatch does. Correct usage (including a generic `Box[K]` with a
  matching `K`, and the `collections` `Counter`/`defaultdict`/`OrderedDict`
  surfaces) is unaffected.
- **A `fn(...) -> T`-typed parameter now rejects a non-function argument**
  (I#1104, first-class function values / #163). Passing a value that is not a
  function to a function-typed parameter — e.g. `takes(7)` where `takes` expects
  `fn() -> int64` — used to compile silently and coerce the scalar word into a
  closure-record pointer slot. Such a call now raises `ZAP4021`, the sibling of
  the #465 fn-value *signature*-mismatch check. A legitimate function value
  (named function, lambda, closure, or a signature-erased value read back from a
  collection element — the D-0067 round-trip) still passes.
