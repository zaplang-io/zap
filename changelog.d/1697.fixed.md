- **A dependency can import its own nested submodule** (I#1697,
  decisions/tooling/1697-dependency-self-reference-nested-module.md). A package
  that ships a nested module at `src/<name>/<sub>.zap` and imports it from its
  own code as `<name>.<sub>` compiled standalone but failed with
  `error[ZAP3010]: cannot find module '<name>.<sub>' in dependency '<name>'`
  when the package was pulled in as a `zenv` path/registry dependency: the
  module linker stripped the leading `<name>` segment and looked for
  `src/<sub>.zap`. A dependency's import of its **own** package (the importing
  file lives in that package's `src/`) now keeps the full dotted path —
  `<name>.<sub>` → `src/<name>/<sub>.zap` — resolving identically whether the
  package is the root project or a dependency. The cross-package convention
  (a consumer's `import <dep>.<sub>` → `<dep>/src/<sub>.zap`) is unchanged. This
  unblocks libraries with nested internal modules (`fastzap` → `validation`).
