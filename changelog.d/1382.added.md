- **`iter()` / `next()` — explicit iterator access** (I#1382 phase 2,
  decisions/lang/1382-iter-next-builtins.md). `iter(x)` obtains an explicit
  D-0048 iterator over a generator, a generator expression, or a user type
  implementing `__iter__` / `__next__`, and is idempotent on an iterator (a live
  view, not a snapshot). `next(it)` steps it and raises a catchable
  `StopIteration` at exhaustion; `next(it, default)` returns `default` instead and
  never raises. Both are built on the comma-ok `__next__ -> (T, bool)` internally,
  so the iteration hot path stays exception-free, and `next(iter(xs))` is
  statically the exact element type. Reified per-container iterators
  (`iter([1, 2])`, `iter("ab")`) remain a follow-up (#1382 phase 3) — a clean
  compile error points there, and `for` iterates every built-in container today.
