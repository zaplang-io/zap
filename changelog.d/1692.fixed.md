- **`argparse` object model — explicit boolean defaults for `store_true` /
  `store_false` flags are no longer discarded** (I#1692,
  decisions/lang/1692-flag-explicit-defaults.md). `ArgumentParser._add` used to
  overwrite any supplied `default` with the action's implied value, so
  `add_argument("--enabled", action="store_true", default="true")` silently
  defaulted to `False`. An explicit `"true"`/`"false"` now seeds the absent flag
  verbatim (read back through `get_flag`), while an absent flag with an explicit
  default stays `has()`-false — it is not treated as supplied on argv. With
  `default` omitted the action default is unchanged (`False` for `store_true`,
  `True` for `store_false`), and supplying the flag still applies its action and
  consumes no value. An invalid boolean default (anything other than `"true"` /
  `"false"`) now raises a catchable `ValueError` at `add_argument` time rather
  than quietly defaulting to `False`.
