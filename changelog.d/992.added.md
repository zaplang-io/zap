- **`net` — DNS resolution surface** (I#992, epic #985,
  decisions/stdlib/992-dns-resolution.md). An explicit name-resolution surface,
  matching Go's `net.LookupHost`/`LookupIP`/`LookupAddr` and Python's
  `socket.getaddrinfo`/`gethostbyname`, so code can resolve, pre-resolve/cache,
  pick a family, and reverse-resolve itself instead of only resolving implicitly
  inside `net.connect`. **Surface:** `net.lookup_host(name) -> list[str]` (all
  addresses, A + AAAA, as numeric IP strings); `net.lookup_ipv4(name)` /
  `net.lookup_ipv6(name)` restrict to one family; `net.lookup_addr(ip) ->
  list[str]` is the reverse (PTR) lookup of a numeric IP (empty list when the
  address has no reverse record; `ValueError` for a non-numeric `ip`). Resolved
  addresses feed the existing `net.connect(ip, port)` /
  `net.connect_ip_deadline` directly. Divergences from Python
  (`docs/PYTHON_DIFFERENCES.md`): results are plain `list[str]`, not
  `getaddrinfo` 5-tuples or a `gethostbyaddr` triple; address family is selected
  by the function name (`lookup_ipv4`/`lookup_ipv6`) rather than an `AF_*`
  constant; a missing reverse record is an empty list, not an exception; no
  service-name (`"http"`→80) resolution. `net` remains Experimental.
