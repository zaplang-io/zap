- **Bare `None` now lowers in an `Optional[T]` struct field and
  `list[Optional[T]]` element** (I#1075, I#1080,
  decisions/lang/1075-bare-none-optional-lowering.md). A bare `None` written
  where an `Optional[T]` is expected but the `None` itself carried no type
  context used to fail IR lowering with `error[ZAP6001]: this expression is not
  supported by codegen yet (Phase 1 slice)`, even though it type-checked.
  `Box(None)` / `Box(item=None)` for an `Optional[T]` constructor field (scalar
  or reference payload, including an omitted field's `= None` default) and
  `[None]` / `[None for _ in range(n)]` / `xs.append(None)` for a
  `list[Optional[T]]` element now lower to the canonical empty option
  (generalizing the #564 argument/return fix to every type-contextual position).
  A bare `None` supplied for a **non-optional** field or element is still
  rejected, now with a clear `None is not a valid \`<type>\` value` message
  instead of the opaque Phase-1-slice bail.
