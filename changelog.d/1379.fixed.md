- **A `bigint` is no longer silently accepted into a fixed-width numeric
  `Optional` payload or struct field** (I#1379). `Optional.Some(<bigint>)`, a
  bare-payload reassignment / call argument into an `Optional[int64]`
  (`Optional[int64] x = None; x = 9223372036854775808`), and a struct field of a
  fixed-width type all accepted a `bigint` value — including the literal
  `-9223372036854775808` (i64::MIN magnitude, which overflows `int64` and is a
  `bigint`) — and **mis-compiled** it: the `bigint` heap pointer was stored
  directly into the scalar slot, so a later `is_some()` / `unwrap()` / field read
  reinterpreted the pointer bits as the value (or, for a tagged `Optional`, read
  it as `None` and raised) — a memory-unsafe result in a checked program. A
  `bigint` is not implicitly convertible to a fixed-width numeric (the direct
  bindings `int64 x = <bigint>` and `float64 f = <bigint>` are already rejected),
  so these positions now reject it the same way with `error[ZAP4001]` instead of
  mis-compiling. A genuine `Optional[bigint]`, and any in-range integer payload,
  are unaffected. (Consequently `int64::MIN` remains unspellable as a literal in
  every position — consistent with the direct binding; convert explicitly where a
  `bigint` is intended.)
