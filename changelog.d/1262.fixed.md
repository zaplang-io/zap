- **A bare payload for an `Optional[T]` field/slot no longer crashes — it wraps
  to `Some`** (I#1262, decisions/lang/1262-optional-scalar-coercion.md). A bare
  scalar keyword such as `Delta(day=1)` for an `Optional[int64]` struct field
  (and the other positions sema accepts a bare payload in — positional
  constructor fields, field assignment `obj.field = 1`, index/key assignment
  `xs[0] = 1` / `m[k] = 1`, and `.append(1)`) used to be stored *unboxed*: IR
  lowering emitted the raw `int` straight into the Optional field with no `Some`
  allocation or discriminant tag, so a later `.unwrap()`/`is_some()`
  dereferenced the integer as an Optional object and segfaulted — a
  memory-safety violation in a checked program. The bare payload now lowers to a
  tagged `Some(payload)`, the symmetric partner of the bare-`None` lowering
  (I#1075/I#1080) in the same coercion chokepoint, so scalar and reference
  payloads both read back correctly. Bare payloads in `return` / `Optional[T]`
  parameter / typed-binding / list-literal positions remain clean sema type
  errors; whether they should implicitly widen too is deferred to I#1265.
