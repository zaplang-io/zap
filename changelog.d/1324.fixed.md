- **A generic free function parameter named `self` no longer mis-lowers**
  (I#1324, decisions/lang/1324-generic-self-param.md). `self` is only a method
  receiver inside a method; in a free function it is an ordinary parameter.
  Monomorphization was special-casing every `self`-named parameter as a receiver,
  so a generic `def g[T](T self): …` kept `self: T` unsubstituted (→
  `ZAP6001: field access on a non-struct value` when the body did
  `reflect.field(self, …)`) and could not infer `T` from a `g(value)` call. Both
  the type substitution (`rewrite_fn_inner`) and the type-argument inference
  (`infer_fn_targs`) now treat a `self` parameter as a receiver only when the
  function actually is a method; a free function's `self` is substituted and
  inferred like any other parameter. Methods are unchanged, and a non-generic
  `self` parameter was already fine. (Surfaced by `@derive` generators, which
  naturally name their parameter `self`.)
