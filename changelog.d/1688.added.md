- **Reserved numeric-width type names rejected with a clear diagnostic (ZAP4091)**
  (I#1688, #1654, decisions/lang/1654-fixed-width-integer-semantics.md rule 8).
  The type names `float8`/`f8`, `float16`/`f16`, `int128`/`i128`,
  `uint128`/`u128`, and `isize` are now recognized in a type position and
  rejected as reserved for a future version of Zap — rather than silently
  resolving to an opaque unknown type or being mistaken for a user-defined type.
  They carry no semantics yet; use an available width (`int64`/`uint64`/`float64`
  or a narrower one) until the reserved type lands. `usize` is implemented (#552)
  and is unaffected. The reservation covers every type position — variable,
  field, parameter, and return annotations, and container element positions such
  as `list[int128]` and `dict[isize, V]`. Reserving the names as *identifiers*
  (so `int128 = 5` as a binding name is also rejected) is a documented follow-up:
  it needs a lexer change and the type-position reservation stands on its own.
