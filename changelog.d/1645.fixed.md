- **A returning decorator with positional metadata around a non-last handler
  parameter now composes correctly** (I#1645,
  decisions/lang/1645-adapter-positional-metadata.md). When the argparse seam
  parameter `fn([C,] Namespace) -> R` is not last, the decorator's positional
  metadata arguments are routed *around* the handler's slot — bound by the
  non-handler parameter names, skipping the handler — so a positional never lands
  on (or double-binds) the handler parameter the adapter fills by name. For
  `argument(str name, fn(Namespace) handler, str metavar = "")`, `@cli.argument(
  "x", "META")` desugars to `cli.argument("x", metavar="META",
  handler=greet$adapter)`. The handler-last case (#1544) and the keyword-only
  metadata case (#1626, the approved CLI surface's `name=`/`help=`) are byte-for-
  byte unchanged.
