- **Struct constructor fields are now type-checked** (I#1464, Phase 2 of #1452).
  A field argument in `StructName(...)` must be assignable to the field's declared
  type, exactly as the equivalent direct binding is — so `struct S: int64 x` then
  `S("hi")`, `S(1.5)`, or a narrowing `S(int64Value)` into an `int32` field is now
  an `error[ZAP4064]` at type-check time (through `zap check` / the MCP
  `check_source` tool / the LSP, as well as `zap build`), instead of compiling and
  silently mis-compiling. This includes the memory-safety cases that were caught
  only in IR lowering before — a `bigint` into a fixed-width-numeric field (#1379)
  and an `Optional[U]` into an `Optional[T]` field with a different payload
  (#1407). **This is a deliberate language tightening:** programs that constructed
  a struct with a mismatched field type (and mis-compiled) no longer compile —
  build the value at the field's type where a conversion is intended. Implicit
  widening is preserved (`int32`→`int64` field, an untyped literal into a numeric
  field, a concrete conformer into an interface field, bare `None` into a nullable
  field, the bare-payload wrap into an `Optional[T]` field); arity and
  unknown-field-name diagnostics are unchanged; and a field typed by a generic
  parameter stays permissive. Struct construction now matches enum-variant
  construction, which was already type-checked.
