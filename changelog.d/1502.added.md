- **A function type may appear inside a tuple generic type argument** (I#1502,
  follow-up to I#1488). `run[(fn(int64) -> int64, int64)]` now parses; before, a
  function type nested in a parenthesized tuple type argument failed to parse
  because the tuple was read as a value expression. `zap fmt` canonicalizes a
  tuple type argument to its paren-free spelling (`run[fn(int64) -> int64,
  int64]`), as it does for every tuple type argument. Because `fn` is a soft
  keyword, a `fn(` element in a subscript or tuple is always read as a function
  type — a variable named `fn` cannot be *called* in that position (an accepted,
  narrow ambiguity, consistent with I#1488).
