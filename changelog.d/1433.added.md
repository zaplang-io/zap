- **Derive synthesis can supply a ported built-in trait's method signature
  internally** (I#1433, epic #1429,
  decisions/lang/1433-derive-builtin-method-sigs.md). When a `@derivable(Trait)`
  generator has no same-named `interface Trait`, the synthesis now supplies the
  dunder signature for a ported built-in trait from an internal table
  (`Eq`→`__eq__`, `Ord`→`__cmp__`, `Hash`→`__hash__`, `Repr`→`__repr__`), so a
  compiler built-in derive can be re-expressed as a library generator even though
  its name collides with the generic operator-overloading interface (`Eq[R]` /
  `Ord[R]`). The fallback is inert for existing programs — it only applies once a
  built-in gains a `@derivable` generator (its port slice) — and a non-built-in
  `@derivable` with no interface still gets the clear "no interface" error. This
  is the E4 enabler for porting the built-in derives to the `@derivable`
  mechanism.
