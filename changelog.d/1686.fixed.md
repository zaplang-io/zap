- **Comptime-`if` folding no longer drags unreachable statements past an early
  `return`** (I#1686, decisions/lang/1686-comptime-fold-early-return-ordering.md).
  When a generic specialization folds a top-level `if reflect.type_info(T)…:` to
  a taken branch that unconditionally `return`s / `raise`s, the statements that
  textually followed the `if` are now recognised as unreachable in that
  specialization and dropped, instead of being lowered into the taken path. The
  "check the type, else fall through to a fallback" idiom

  ```zap
  def resolve[T](T value) -> T:
      if reflect.type_info(T).name == "str":
          return value
      raise ValueError("unsupported")
  ```

  now returns its value on the supported specialization (previously the trailing
  `raise` ran anyway); the unsupported specialization still reaches the fallback.
  Ordinary non-generic code, runtime `if`s, and fall-through (non-diverging)
  folded branches are unaffected.
