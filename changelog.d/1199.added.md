- **Operators are now nameable as generic bounds** (I#1199,
  decisions/lang/1199-operator-capability-interfaces.md; builds on the reflected
  operators of #1180/#1198 and the generics epic #1204). The prelude declares
  the forward (`Add[R, Out]`, `Sub`, `Mul`, …, `Eq[R]`, `Ord[R]`) and reflected
  (`RAdd[L, Out]`, …, `RMul`, `REq[L]`, `RCmp[L]`) operator-capability
  interfaces, so a generic can require an operator and name its result type:
  `def scale_all[T: RMul[f64, T]](list[T] xs, f64 k) -> list[T]: return [k * x
  for x in xs]`. Inside such a body the operator type-checks through the bound
  (the result is the interface's substituted `Out`), and the bound is enforced
  structurally at each instantiation (static dispatch, no fat pointer). The
  existing `Equatable` / `Comparable` capability bounds now also permit the
  corresponding operators (`==`, `<`, …) on a bounded type parameter. Concrete
  `a OP b` dispatch is unchanged — this is purely additive, adding only the
  bound surface — and operator-free or non-generic programs are unaffected
  (the interfaces are injected only when a bound actually names one).
