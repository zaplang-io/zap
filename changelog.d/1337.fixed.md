- **A type mismatch through a struct field read is now caught** (I#1337,
  decisions/lang/1337-sema-field-read-typing.md). Sema's value inference for an
  attribute access (`Expr::Attr` on a value base) returned `Unknown` for a struct
  field read, so a mismatch flowing through a field — `int64 x = self.some_list`,
  a field passed where the parameter type disagrees, a chained `self.inner.v` —
  was silently accepted, while the identical mismatch through a local binding was
  flagged (`ZAP4001`). The field read now yields the field's declared type, so
  the mismatch is reported at the read site (assignment `ZAP4001`, argument
  `ZAP4021`), and the field-read span is recorded in the inferred-type map the
  monomorphizer consults (#1167). Correct field reads — scalar, nested, and
  container — are unchanged; a generic struct's type-parameter-typed field stays
  `Unknown` (fail-closed, since the type model carries no type arguments); and an
  undeclared attribute still infers loosely (no new "unknown field" diagnostic).
