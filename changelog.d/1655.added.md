- **The argparse-backed handler adapter now binds `char`, `bytes`, `bigint` and
  `complex` handler parameters** (I#1655, decisions/lang/1655-namespace-nonnumeric-getters.md).
  The object-model `Namespace` gains four typed getters — `get_bytes(name)` (the
  argument string's UTF-8 encoding), `get_char(name)` (a single Unicode codepoint),
  and `get_bigint(name)` / `get_complex(name)` (which parse the argument string,
  #1657) — and a handler declaring any of these parameters adapts through them
  (e.g. `show$impl(ns.get_bigint("n"), ns.get_complex("z"))`) instead of being a
  decoration-site `ZAP5048`. A malformed `char`/`bigint`/`complex` argument raises
  a catchable `ValueError`. Unlike the narrowing numeric scalars (#1625) these read
  the typed getter directly, with no conversion wrapper. Part of epic #1644; only
  `int8`/`int16` (#1654, not scalar value types in Zap) remain a precise `ZAP5048`.
