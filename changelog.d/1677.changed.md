- **Fixed-width integer arithmetic now wraps at the declared width at runtime**
  (I#1677, decisions/lang/1654-fixed-width-integer-semantics.md; the codegen
  half of the width-stable change begun in I#1676). Scalar integer arithmetic
  was computed at a 64-bit width in the `zapc_ir` lowering regardless of the
  operand types, so a narrow result did not wrap even though sema typed it as
  the narrow type. The lowering now narrows each arithmetic result back to the
  width-stable result type (two's-complement wrap): `uint8(200) + uint8(100)`
  evaluates to `44` (not `300`), `uint16`/`uint32`/`int32` arithmetic wraps at
  `2^16`/`2^32`/`2^31`, a mixed-width operation wraps at the larger operand's
  width, and the counter idiom (`c += 1` on a narrow `c`) wraps there. `int64` /
  `uint64` / `usize` arithmetic is unchanged, and the explicit `uintN(...)` /
  `intN(...)` conversion still wraps as before (D-0019 / D-0020). `zapc_mono`'s
  generic-argument inference is aligned to the same width-stable rule. This is
  the observable runtime completion of the I#1676 type-system break.
