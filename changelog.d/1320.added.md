- **Typed errors across the `os` / `fs` / `io` / `process` surface** (I#1320,
  decisions/lang/1320-os-fs-typed-errors.md), generalizing the #1311 read-path
  typing. An errno-driven OS/filesystem failure now raises `OSError`, and a
  missing path raises `FileNotFoundError` (`os.listdir`, `fs.size`/`stat`/
  `rename`/`move`/`copy`/`scandir`/`walk`/`makedirs`/`rmtree`, `io.open`,
  `os.chdir`/`remove`/`rmdir`, `os.path_abspath`/`realpath`, and the `process`
  spawn path — so a missing executable raises `FileNotFoundError`, as in
  CPython). An allocation failure raises `MemoryError`; a bad `io.open` mode, an
  empty `fs.makedirs` path, or an empty `process` argument list raises
  `ValueError`. `process.run`/`check_run` still raise `RuntimeError` for a
  non-zero child exit, `input()` still raises `EOFError`, and a `process` timeout
  still raises `TimeoutError`. Every type descends from `Exception`, so an
  existing `except Exception` still catches every failure unchanged. Also fixes
  `fs.read_file`/`read_bytes` on a **directory**, which previously aborted with an
  out-of-memory error instead of raising a catchable `OSError`.
