- **`is None` / `== None` now work on every nullable reference type** (I#1179,
  D-0014). A `str` (or `bytes`, interface, reference `struct`, or collection)
  value — a reference type that `None` lowers to as a null pointer per D-0014 —
  could be assigned and defaulted to `None` but could not be *tested* for it:
  `name is None`, `name is not None`, `name == None`, and `name != None` were
  all rejected with `error[ZAP4074]: a value of type 'str' can never be None, so
  this test is always constant`. The null check is now accepted and lowers to a
  real runtime null test, so a function can expose a nullable string argument
  (`def gettz(str name = None)`) and distinguish an omitted or explicit `None`
  from an empty or nonempty string. `== None` / `!= None` behave identically to
  `is None` / `is not None` (SPEC §5). Non-nullable value types — scalars, an
  `enum`, a `value struct`, a tuple — still reject the null check with ZAP4074,
  and `a is b` on two strings is still `ZAP4073` (strings carry no reference
  identity; use `==`). This unblocks the dateutil-compatible `gettz(name=None)`
  signature (zaplang-io/datetime-utils#3).
