- **`decimal` — exact base-10 `Decimal` type (money / billing correctness)**
  (I#981, PR#1093, decisions/stdlib/981-decimal-exact-base10.md, epic #966). A
  software arbitrary-precision decimal built over the prelude `bigint`
  (coefficient + `int64` exponent) — pure prelude Zap, no runtime C. The headline
  guarantee is exactness: `Decimal("0.1") + Decimal("0.2") == Decimal("0.3")`,
  which binary `float64` cannot give. **Surface:** `import decimal` then
  `decimal.Decimal("1.50")` / `decimal.Decimal(42)` (type written bare as
  `Decimal`). **Arithmetic:** `+ - *` are exact (scale preserved); `/` (and
  `d.div(other, prec=28, rounding="ROUND_HALF_EVEN")`) rounds the quotient to a
  per-call precision — there is **no** hidden global context. **Rounding:**
  `d.quantize(Decimal("0.01"), rounding=…)` sets the scale; the default is
  banker's `"ROUND_HALF_EVEN"` and the full eight-mode General Decimal Arithmetic
  set is available as string tags (`ROUND_HALF_UP`/`HALF_DOWN`/`DOWN`/`UP`/
  `FLOOR`/`CEILING`/`05UP`). **No lossy float construction:**
  `decimal.Decimal(<float>)` is a compile error; the explicit
  `decimal.from_float(f)` opt-in converts through the float's shortest
  round-trip string. Also `to_int` (truncate toward zero), `to_integral_value`,
  `exponent`, `is_zero`, comparisons (value equality ignores scale, so
  `1.0 == 1.00`), and `str()` / parsing per the GDAS rules. Divergences from
  Python (see `docs/PYTHON_DIFFERENCES.md`): no global context, no
  `Infinity`/`NaN`, no signed zero, `InvalidOperation`/`DivisionByZero` map to
  `ValueError`, and no `1.50d` literal (construct via `Decimal("1.50")`).
