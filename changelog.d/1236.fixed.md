- **`zap test` now lowers module-level `const`/mutable bindings declared in (or
  imported into) the test module** (I#1236,
  decisions/tooling/1236-zap-test-harness-module-constants.md). A `@test` — or a
  function it calls, or a default argument — can read a top-level `const T NAME =
  expr` (#658) or mutable `T NAME = expr` (#662), scalar or value-struct
  (including a struct with a reference field, the timezone/Easter shape), with
  initialization order preserved. The harness transform dropped every top-level
  statement, so these bindings never reached codegen and native `zap test`
  failed with `error[ZAP6001]: unknown variable '<NAME>'` even though sema
  accepted the module; this blocked the native-test migration for packages such
  as `datetime-utils`. Test discovery, reporting, and ordinary `zap run`/`build`
  behavior are unchanged. Builds on #1232 (the import/sema side of the same
  `zap test` path).
