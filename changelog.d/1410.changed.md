- **The netpoller tracks timer deadlines in a min-heap instead of a linear scan**
  (I#1410, decisions/runtime/1410-netpoller-deadline-min-heap.md). Finding the
  nearest deadline for `epoll_wait` and waking expired sleeps/timers/IO-deadlines
  is now O(1) / O(log n) per poll tick instead of O(n) over every live descriptor,
  so many concurrent `time.sleep`s / `time.after` timers no longer slow the poll
  loop. Purely internal: no surface change, and `time.sleep` / `time.after` / timer
  behavior and all goldens are unchanged.
