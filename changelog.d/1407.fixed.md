- **An `Optional[U]` value is no longer silently accepted where an `Optional[T]`
  with a different payload is expected** (I#1407). Because sema erases the
  `Optional` payload (it tracks every `Optional[T]` as opaque `Named("Optional")`),
  an explicit `Optional.Some(v)` whose argument monomorphizes a *different*
  payload — `Optional.Some(g)` for a `bigint g`, `Optional.Some(n)` for an
  `int32 n`, or a `str` value — into an `Optional[int64]` binding, reassignment,
  call argument, return, constructor field, or collection element was accepted and
  **mis-compiled**: the `Optional$U` pointer was stored raw into the `Optional$T`
  slot, whose layout and method dispatch disagree, so a later `is_some()` /
  `unwrap()` read garbage or raised — a memory-unsafe result in a checked program.
  This is the sibling of the bare-`bigint` case fixed in I#1379 (a value whose
  `Optional` has already monomorphized `Optional$U` slips the bare-payload width
  check). These positions now reject a payload mismatch with `error[ZAP4001]`
  instead of mis-compiling. A matching-payload `Optional` (`Optional[bigint] x =
  Optional.Some(g)`, `Optional[int64] y = x`), a nested `Optional[Optional[T]]`,
  and the bare-payload widening (`Optional[int64] x = n` for an in-range numeric
  `n`) are unaffected; build the target payload explicitly where a conversion is
  intended (e.g. `Optional.Some(int64(n))`).
