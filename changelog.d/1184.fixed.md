- **`assert x == None` / `assert x != None` on a nullable reference now
  compiles** (I#1184). The power-assert decomposition (D-0054) evaluates a
  comparison's two operands separately so a failure can report both values, but
  a bare `None` literal has no standalone lowering (it exists only as the
  null/empty-variant check the expression lowerer intercepts), so an `assert`
  whose top-level operator was `== None` / `!= None` failed to compile with
  `error[ZAP6001]: this expression is not supported by codegen yet (Phase 1
  slice)` — even though the same comparison worked in an `if`, in an assignment,
  and as `assert x is None`. `== None` / `!= None` are now excluded from the
  decomposition and fall through to the whole-expression null check (a real
  `IsNull` runtime test, SPEC §5), so `assert client.reader == None` on a
  nullable struct field compiles and runs. Ordinary comparisons (`assert a ==
  b`) still show their operand values. Unblocks the lifecycle regression suite
  in zaplang-io/memcached#12.
