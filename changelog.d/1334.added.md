- **Ordering comparisons on `set` and `deque`** (I#1334,
  decisions/lang/1334-collection-ordering.md), the ordering sibling of the
  structural-equality fix (#1328). `set` now supports Python's subset/superset
  partial order (`a <= b` subset, `a < b` proper subset, `a >= b`/`a > b`
  superset / proper superset; incomparable sets give `False` both ways). `deque`
  now orders lexicographically like Python's `collections.deque` (element-wise,
  with a shorter prefix sorting first). Element ordering reuses scalar `<`/`>`.
- **`< <= > >=` on `dict`, `heap`, and `oset` are now a compile-time error**
  (ZAP4012): dicts are not orderable (as in Python), a heap's internal order is
  implementation-defined, and an ordered set has no unambiguous ordering. `is` /
  `is not` identity stay available. Previously all of these silently
  pointer-compared the container headers, yielding a meaningless result.
