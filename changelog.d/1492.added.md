- **`NullReferenceError` — built-in exception for a null reference dereference**
  (I#1492, Epic I#1489, decisions/lang/1489-null-reference-error.md). A new
  catchable built-in exception type, `NullReferenceError`, directly under
  `Exception` (flat — CPython-shaped, like `None.attr` → `AttributeError`, not
  under `RuntimeError`). `raise NullReferenceError("…")` constructs it, and both
  `except NullReferenceError` and `except Exception` catch it, while an unrelated
  clause (e.g. `except ValueError`) does not; a re-raise preserves its type. Its
  message is a **located** string — the source location is required, and the
  field name and owning static type are included when known, e.g.
  `null dereference reading field 'name' of 'Node' at foo.zap:7`. This PR defines
  the type, its hierarchy placement, and the message shape only; making a null
  (non-`Optional`) reference dereference actually *raise* it instead of crashing
  with `SIGSEGV` is the follow-up I#1493.
