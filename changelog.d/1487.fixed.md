- **A user binding named `reflect` is no longer hijacked by the reflection
  module special-cases** (I#1487). The monomorphizer's `reflect.construct(T)`
  rewrite (and the `reflect.type_info(T).name` value-fold) keyed only on the
  receiver being literally named `reflect`, without checking — as the sibling
  `datetime.zone_abbreviation` special-case does — that the name is unshadowed.
  A local, parameter, or field named `reflect` whose type declared its own
  `construct` was intercepted by the reflection rewrite and failed
  monomorphization with `error[ZAP6001]: reflect.construct(T) expects a type
  name`. Both `reflect` special-cases now skip when `reflect` resolves to a
  value binding in scope, so such a call dispatches to the user's own method;
  genuine reflection use (where `reflect` is the unshadowed module) is
  unchanged.
