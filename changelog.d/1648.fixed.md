- **`str.ljust`/`rjust`/`center` accept a multibyte fill character** (I#1648,
  decisions/stdlib/1648-pad-unicode-fill.md, superseding D-0210's ASCII-fill-byte
  clause). The shared pad helper copied only the fill's first byte, so a
  multibyte fill produced **invalid UTF-8** (`"x".ljust(3, "é")` gave bytes
  `78 C3 C3`); it now repeats the whole fill codepoint (`"xéé"`). Width is still
  counted in codepoints. A fill that is not exactly one codepoint (empty or
  multi-character) now raises a catchable `TypeError` matching CPython, instead
  of silently defaulting to a space or using the first byte. The default space
  fill, ASCII fills, and `zfill` are unchanged.
