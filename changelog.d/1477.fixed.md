- **A user type's own `get` method is no longer hijacked by the builtin
  `dict.get` special-casing** (I#1477). The monomorphizer's `dict.get(key) ->
  Optional[V]` rewrite used the call's expected `Optional[..]` type as a
  fallback value type when the receiver's type was opaque. That fallback also
  fired for a *concrete* receiver — a user `struct`/`enum` with its own `get`
  method — whenever the call's binding or return type happened to be
  `Optional[..]`, forging a bogus `get$Optional$V` symbol that no such method
  existed under and aborting IR lowering with `error[ZAP6001]: no method
  'get$Optional$bytes' on that value`. A generic homonym such as `Typed[T].get`
  was not required to trigger it; the expected-type context alone did. The
  dict rewrite is now skipped when the receiver is a user type that declares
  its own `get`, so such a call dispatches as the plain user method — while a
  genuine `dict` receiver (or one opaque to the inferer, e.g. a type parameter)
  still specializes as before. Unblocks zaplang-io/memcached#9.
