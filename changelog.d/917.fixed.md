- **`zap test` and the runtime build cache no longer race on temp names** (I#917,
  follow-up to I#180 / PR#916). Throwaway paths were named from a
  `SystemTime`-nanosecond reading, which on a microsecond-quantised clock (macOS)
  could hand two callers in the same tick the same path. `zap test`'s per-file
  test binary (`zaptest-<stem>-…`) now carries the process id plus a
  process-global counter instead of a clock reading, so two concurrent runs — or
  one run compiling two same-named entry files — can no longer be handed the same
  throwaway binary and clobber each other; the LTO-bitcode and object runtime
  caches (`zaprt-<key>.…tmp[.o]`) are keyed the same way, so two threads compiling
  the same cache entry no longer write the same temp and race its atomic publish.
  The remaining in-process test fixtures (module linker, diagnostics render tests)
  are deflaked by the same mechanism.
