- **`type_info(T).kind` switch + container recursion (E2)** (I#1253, epic #1249,
  decisions/lang/1253-kind-switch.md). Comptime branching on a type's `.kind`
  plus resolving a container's element back to a nested `TypeInfo`, so container
  families (`list[T]` / `dict[K,V]` / `T?` / tuple) are handled by comptime
  recursion on `.kind` — no `impl`/conformance machinery (#1248 HQ2). A no-sema
  `TypeRegistry` (built from the concrete AST) resolves a container's
  `.elem`/`.key`/`.value`/`.inner`/`.elems` and a field's `.ty` to a nested
  `TypeInfo` (finishing the `.ty` deferral from #1250); the seven `TypeKind`
  constants are seeded so a kind-switch reads `if info.kind == List:`. The dict
  arm walks key-then-value **structurally**, never by iterating a map, so no
  seed-dependent order leaks (#1066). `reflect.has_override(info, "serialize")`
  lets a kind-switch short-circuit to a user handler (#1248). The recursion is
  type-structural and depth-bounded (recursive type shapes terminate with a
  diagnostic, the central cap is #1254), so the evaluator's no-recursion rule is
  unchanged. Wired to mono (`type_registry`). Compiler-internal and host-tested;
  **no `reflect`/`comptime` keyword surface yet** (that, and the codec that
  consumes the kind-switch, are follow-ups); no behavior change for existing
  programs.
