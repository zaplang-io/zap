- **`http.parse_set_cookie` — distinguish an absent `Max-Age` from a valid
  non-positive one** (#1524, amends D-0231,
  decisions/stdlib/1524-cookie-max-age-optional.md). The parsed `Cookie`'s
  `max_age` field used to be an `int64` that returned `-1` BOTH when `Max-Age`
  was absent and when the wire value was a valid `-1`, so a caller could not tell
  a session cookie apart from one RFC 6265 §5.2.2 deletes immediately. `max_age`
  is now `Optional[int64]`: `None` for an absent or malformed attribute, and
  `Some(n)` for a parsed value — including `Some(0)` and `Some(-1)`. This unblocks
  `zaplang-io/requests`#3, which can now apply `Max-Age`/`Expires` precedence off
  the typed result without reparsing the header. `http` is Experimental.
