- **A method call on a null built-in reference value now raises a located
  `NullReferenceError` instead of crashing** (I#1493 part B, Epic I#1489,
  decisions/lang/1489-null-reference-error.md). Calling a method on a null
  non-`Optional` `list` / `str` / `dict` / `set` / `bytes` / … —
  `null_list.append(x)`, `null_str.upper()`, etc., where the field was left
  unset — previously SIGSEGV'd and now raises `NullReferenceError`, which
  `except NullReferenceError` and `except Exception` catch, with a located
  message (e.g. `null dereference calling method 'upper' on 'str' at foo.zap:7`).
  A method call on a null **user-struct** receiver (`n.method()`) remains covered
  transitively by the field read/store guards inside the method body (PR#1511),
  as do `n[i]` / `for x in n` over a user type via their `__getitem__` /
  `__iter__`; `Optional[T]` keeps its own `None`/unwrap path and is unaffected.
