- **`collections` — `Counter` / `defaultdict` / `OrderedDict`** (I#972,
  decisions/stdlib/972-collections-conveniences.md, epic #966). The Python
  `collections` conveniences, each a generic prelude struct over the built-in
  `dict`/`list` (#812) — pure prelude Zap, no runtime C. **Surface:** `import
  collections` then `collections.Counter[K]` / `collections.defaultdict[K, V]` /
  `collections.OrderedDict[K, V]` (module-qualified seam sugar, D-0202, over the
  backing structs `CounterMap`/`DefaultDict`/`OrderedMap` — so the Python name
  `Counter` does not collide with the lock-free `concurrent.Counter`). All three
  are Pythonic via the index/membership/size dunders: `c[k]`, `c[k] = n`,
  `k in c`, `len(c)`. **`Counter`** — a multiset over `dict[K, int64]`: construct
  from an iterable or empty; `c[k]`/`get(k)` read `0` for a missing key;
  `add(key, n=1)`, `subtract(key, n=1)` (keeps non-positive counts, like Python),
  `update(items)`, `total()`, `elements()`, `keys()`, `most_common(n=-1)` (count
  descending; `n < 0` returns all), and `+`/`-` (which drop non-positive
  results). **`defaultdict`** — autovivifies a missing key from a `fn() -> V`
  factory on `d[k]` access, so `d[key].append(x)` groups without a prior check;
  `k in d` and `get(k, fallback)` are read-only and never create the key.
  **`OrderedDict`** — an insertion-ordered map (a real gap: built-in `dict`
  iteration order is unspecified/seeded, D-0235), composing `dict` + an ordered
  key `list`; `keys`/`values`/`items` iterate in insertion order, plus
  `move_to_end` and `delete`. Divergences from Python
  (see `docs/PYTHON_DIFFERENCES.md`): `most_common` tie order among equal counts
  is unspecified (not insertion order, D-0235); `Counter`/`defaultdict` key order
  is unspecified; `namedtuple` is not provided — use a `value struct` (a strict
  superset: named, immutable, `@derive(Eq, Ord, Repr)`), or a tuple for the
  anonymous case.
