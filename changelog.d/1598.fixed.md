- **`list.sort` / `sorted` no longer abort when a sort scratch allocation fails**
  (I#1598, decisions/lang/1598-sort-alloc-memoryerror.md). `zap_list_sort_by`
  allocates three temporary index buffers before it touches the list; a failure
  there printed `zap: out of memory sorting a list of N` and `abort()`ed, and both
  call sites lowered through a plain call so even a raised exception would have
  unwound past a local handler. The failure now releases any sibling scratch that
  already succeeded and raises a catchable `MemoryError` (SPEC §10, #1581), and
  both `list.sort(...)` and `sorted(...)` lower through an invoke so
  `try`/`except MemoryError` catches it. Because the buffers are allocated before
  any element moves, a caught failure leaves the input list in its original order,
  so the sort is safely retryable.
