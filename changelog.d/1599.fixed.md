- **A failed string scratch-buffer growth no longer leaks the old allocation**
  (I#1599). `zap_strbuf_ensure` — shared by `str.expandtabs`, `str.translate`,
  and `str.format_map` — assigned `realloc`'s result straight back into its
  buffer before the `NULL` check. On a growth failure libc leaves the earlier
  allocation live, so the helper lost its only pointer and then raised
  `MemoryError`; a caller that caught and retried leaked one buffer per failure.
  The grow now goes through a temporary and `free()`s the old buffer before
  raising. No observable behavior change on the success path (the three methods
  return the same strings); it closes the leak on the catchable-failure path.
