- **Iterating or indexing a `list[bool]` (or `list[char]`) yields a value that
  appends back into the same list** (I#1241,
  decisions/lang/1241-bool-char-element-read-back-narrows.md). A `bool` read from
  a `list[bool]` — by `for value in xs`, by `xs[i]`, or by a comprehension — used
  to come back typed as the `i64` storage word, so re-appending or re-storing it
  into a `list[bool]` failed IR lowering with `error[ZAP6001]: append() value has
  the wrong element type`, even though the identical iterate+append pattern on
  `list[int64]`, `list[float64]`, and `list[str]` worked. A `bool`/`char` element
  now reads back as its narrow scalar type (`bool`/`char`), matching how
  string iteration already yields a `char`, so it round-trips through the
  element-kind check — directly (`for v in xs: out.append(v)`), through a generic
  `[T]` helper, and from a `list[bool]` extracted from an enum variant. Appending
  a genuinely wrong kind to a `list[bool]` (a `str`, an `f64`, or a bare integer
  literal) is still rejected with the same `ZAP6001`, and a `bool`/`char` element
  read back and printed now renders `True`/`False` / `'c'` rather than its integer
  word.
