- **The argparse-backed handler adapter now injects `Depends(...)` parameters**
  (I#1646, decisions/lang/1646-adapter-injected-depends.md). An adapted CLI handler
  may declare, in any position, a parameter whose default is `Depends(provider)`;
  the adapter resolves it from its provider in the adapter body (reusing the
  D-0092 resolver — deps-first, one `<provider>$dep` local per distinct provider,
  nested `Depends` recursively, cycle-detected) and passes it to the handler, while
  the first non-scalar parameter remains the dispatcher-supplied context (#1621)
  and scalars bind from the `Namespace`. A `Depends` parameter does not widen the
  `fn([C,] Namespace)` seam. A `@request_source` parameter (#959) is a precise
  error here — a command-line handler has no request value to resolve against — and
  any other non-injectable, non-scalar parameter remains `ZAP5048`. Handlers with
  no `Depends` parameter are unchanged.
