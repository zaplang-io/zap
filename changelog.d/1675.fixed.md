- **An exhaustive set of enum-variant `match` arms now elides a trailing
  unreachable arm before lowering** (I#1675,
  decisions/lang/1675-enum-exhaustive-arm-elision.md). A generic that matches a
  value of an enum type parameter over every variant and then has a `case _:`
  fallback — type-correct only for a different specialization — used to fail to
  compile for the enum specialization with `ZAP4001: value of type enum#0 is not
  a function`, because the unreachable `_` body was still lowered. Once the
  unguarded arms cover every variant (counting bare variant patterns, bare-binder
  payloads, and or-patterns; a guard or a refutable payload does not count), the
  remaining arms are dropped — the enum analog of the #1668 irrefutable-arm
  elision and the dual of #1326, behaviour-preserving since an arm after an
  exhaustive match never runs. Both tier-1 and tier-3 (payload) enums are
  covered. A non-exhaustive match keeps its trailing arms live.
