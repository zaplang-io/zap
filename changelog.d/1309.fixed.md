- **An `Optional[T]` (or any generic instance) returned by an interface method
  keeps its type through lowering** (I#1309,
  decisions/lang/1309-interface-signature-monomorphization.md). A method call on
  the value returned by a dynamic interface call — for example
  `reader.end_time().is_some()` on an `interface Reader` whose `end_time`
  returns `Optional[int64]`, directly or through an `auto` binding — used to fail
  IR lowering with `error[ZAP6001]: method call on a non-struct value`, even
  though sema accepted the program and the equivalent ordinary function compiled.
  Monomorphization passed interface declarations through verbatim, so a method's
  `Optional[int64]` return annotation was never renamed to its concrete instance
  (`Optional$int64`) nor emitted, and lowering resolved the un-mangled head with
  its type arguments ignored. Non-generic interface method signatures are now
  rewritten exactly like struct fields and function signatures, so the returned
  `Optional` resolves to its real struct type and its methods dispatch. Works for
  scalar and reference payloads, nested generics (`Optional[list[int64]]`),
  inherited refined-supertype methods (#830), and interfaces imported from
  another module. Generic interfaces are unchanged.
