- **A bare `None` argument to an enum-variant constructor now lowers instead of
  bailing** (I#1367). `Enum.Variant(None)` for a variant field of a nullable type
  used to fail IR lowering with `error[ZAP6001]: this expression is not supported
  by codegen yet (Phase 1 slice)`, even though it type-checked — because the
  enum-variant constructor lowered its payload argument with a typeless
  `self.expr`, unlike struct-constructor fields (#1075). This blocked
  constructing a nested `Optional` (`Optional.Some(None)` for an
  `Optional[Optional[T]]` — a valid outer-present / inner-absent value) and any
  enum variant carrying an `Optional[T]` (or other reference) field with a bare
  `None` (e.g. `E.V(None)`). The argument now lowers against the field's declared
  type through the same type-contextual chokepoint struct fields, call arguments
  and returns use, so a bare `None` becomes the field's canonical empty value
  (the tagged `None` of a nested `Optional`, the null of a reference), a bare
  payload auto-wraps into `Some` where accepted (#1262), and a bare `None` for a
  non-nullable scalar variant field now gives the clear `None is not a valid
  \`<type>\`` error instead of the opaque `ZAP6001`.
