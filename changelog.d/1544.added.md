- **A returning decorator can now adapt a handler of any signature into one
  uniform argparse-backed dispatcher** (I#1544,
  decisions/lang/1544-handler-adapter-synthesis.md). When a returning decorator's
  receiver method declares its handler parameter as the uniform seam
  `fn(Namespace) -> R`, the compiler synthesizes, per decorated handler, an
  adapter `def <name>$adapter(Namespace ns) -> R` that reads each handler
  parameter from the parsed argparse `Namespace` **by name** with the
  type-matched getter (`int`→`get_int`, `float`→`get_float`, `bool`→`get_flag`,
  `str`→`get_str`) and calls the handler **in its declaration order**. The
  decorator chain threads this adapter — a single `fn(Namespace) -> R` value — in
  place of the raw handler, so a package stores and invokes one uniform callable
  regardless of the handler's arity or parameter types (a fixed `fn(...)`
  parameter handled only one shape, #1509/#1519/#1527). Adaptation is fully
  static — no runtime invoke-by-name. This is mechanism **A-argparse** (reusing
  the prelude `Namespace`, no new runtime value type). v1 binds argv-sourced
  scalar parameters (`int`/`float`/`bool`/`str`); a non-scalar parameter is a
  precise decoration-site error (`ZAP5048`); an explicit `Context` parameter and
  a framework-agnostic boxed-value seam are documented follow-ups. A receiver
  method that declares the handler's own fixed signature (e.g. `fn(str) -> str`)
  still receives the raw handler, unchanged. Both local struct and imported-module
  (#1519) receivers are supported. Unblocks zaplang-io/cli#4.
