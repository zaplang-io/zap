- **`iter()` over a built-in container now returns a precise reified iterator**
  (I#1382 phase 3, decisions/lang/1382-phase3-reified-iterators.md). Where phase 2
  left a "phase 3" error, `iter(xs)` on a `list` / `set` / `heap` / `deque` /
  `oset` / `tuple` / `dict` (keys) / `str` (char) / `bytes` (int64) / `range`
  (int64) / array now hands back an iterator over the same elements `for` yields,
  carrying the **exact element type** — so `next(iter(xs))` is the precise `T`,
  `next(it, default)` and `for x in iter(xs)` work, and the iterator conforms to
  `Iterator[T]` so it flows into an `Iterator[T]` parameter. The representation is
  a typed synthesized generator (`iter(c)` reuses the generator-expression
  pipeline), so it carries a precise `(T, bool)` rather than the loose genexpr
  element type.
