- **Generic type-argument inference now reads a unary argument expression**
  (I#1117). A generic constructor or call inferred its type arguments by typing
  each argument expression and unifying against the type parameters, but it
  typed *every* unary expression as unknown — including the arithmetic negation
  a negative literal parses to. So `Optional.Some(-4)` failed with `ZAP6001`
  ("cannot infer type argument 'T'") while the sign-flipped `Optional.Some(4)`
  compiled, and the same gap hit any negative/unary-plus/bit-complemented
  literal fed to a user generic struct, a generic function, or a nested method
  argument. A unary expression is now typed in the inferer — `not x` as `bool`,
  and `-x` / `+x` / `~x` as the operand's type — so a negated literal infers
  exactly the type its bare-literal counterpart does. An argument the inferer
  still cannot type stays unresolved, so a genuinely unconstrained parameter
  (e.g. `Pair(a=-4)` leaving `B` unpinned) is still rejected.
