- **A function type may be written as an explicit generic type argument** (I#1488).
  `run[fn(int64) -> int64](g)` — and the method form `recv.run[fn(int64) ->
  int64](g)` — now parse and resolve, binding the generic parameter to the
  function type. Previously a function type in a `[...]` type-argument subscript
  failed to parse (`error[ZAP2001]: expected ']'`), because a subscript element
  was only ever a value expression and a function type is not one; the only way
  to pass a function value to a generic parameter was to bind it to an
  `fn`-typed variable first (a bare function name or `lambda` cannot pin the
  type parameter by inference). The grammar's `index_elem` now admits a
  `func_type` at the head of a type argument. A function type *nested inside a
  tuple* type argument (`run[(fn(int64) -> int64, int64)]`) is not yet supported.
