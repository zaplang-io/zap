- **`==` / `!=` on `dict`, `set`, `deque`, and `oset` now compare structurally**
  (I#1328, decisions/lang/1328-structural-collection-equality.md), the dict
  counterpart to the list fix (#1239). Two dicts are equal when they have the
  same keys with `==`-equal values (order-independent, Python mapping semantics);
  two sets are equal by membership (order-independent); `deque` and `oset` compare
  order-sensitively and element-wise. Values/elements recurse, so a `dict` whose
  value type supplies its own equality (`str`/`bytes` by contents, a struct's
  `__eq__`, a nested `list`/`dict`) compares correctly — previously these all
  compared by pointer identity, so two separately built but equal containers
  reported unequal. `is` / `is not` are unchanged (reference identity).
- **`==` / `!=` on a `heap` is now a compile-time error** (ZAP4012). A heap's
  internal order is implementation-defined, so value equality is undefined;
  compare a snapshot (e.g. `sorted(h.items())`) or use `is` / `is not` for
  identity. This replaces the previous silent (and meaningless) pointer-identity
  comparison.
