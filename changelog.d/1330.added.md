- **A comptime `@derive` generator can guard on a field's kind and abort with
  `comptime.error` — the comptime surface is wired through sema → mono** (I#1330,
  decisions/lang/1330-comptime-error-surface.md). `comptime.error(f.span, msg)` is
  now accepted by the type checker (like the `reflect.*` builtins) instead of
  failing as an unknown name; the unroll engine propagates its abort as the
  intended compile error rather than swallowing it; a comptime-constant `if` in a
  `comptime for` body is resolved at specialization time (only the taken branch is
  kept, so a guarded `comptime.error` fires only when its branch is taken); and
  the unroll evaluator is given the module's type registry so a `f.ty.kind` guard
  (e.g. `if f.ty.kind.name == "struct": comptime.error(...)`) resolves. A library
  derive generator can therefore reject an unsupported field type at compile time
  with its own message. No change to a program that uses no comptime surface. A
  `comptime <name> = …` binding and a namespaced kind-constant surface remain
  follow-ups; the diagnostic framing (code/span/backtrace) is E3d (#1293).
