- **A `value struct` returned by value and stored into an aggregate field is now
  boxed onto the heap, fixing a dangling-pointer segfault** (I#1400,
  decisions/lang/1400-value-struct-field-boxing.md). A flat `value struct` (or
  tuple) crosses a by-value call/return boundary in a register / `sret` **stack
  spill**; storing that spill's pointer straight into a heap aggregate's field —
  a struct field, a tagged enum-variant payload, or an `Optional.Some` payload
  built by the `#1262` auto-wrap — left the field pointing into the producing
  frame. Once that frame returned the field **dangled**, and a later read of an
  interior reference faulted on the reused slot. The datetime-utils parser hit
  this when a user `tzresolver` returned a `TimeZone` (a value struct with a
  `str name`) by value into `Optional.Some`: after the resolver's frame returned,
  `TimeZone.name` read `NULL` and `datetime.resolve` → the runtime
  `zap_tz_zone_id` segfaulted on the null name. (A control that built the zone
  inline via `datetime.zone`, which heap-allocates, survived — so the defect only
  surfaced across the by-value call boundary.) Such a field store now boxes the
  value struct (a fresh heap `StructNew` + field copy, the same boxing the
  interface-coercion and collection-element paths already perform) through the new
  `copy_field_value` chokepoint, so the container owns heap storage that outlives
  every frame. Covers `Optional.Some(f())` and bare-payload `return f()`
  auto-wrap, struct-field construction `Struct(field=f())` and its defaulted
  fields, and other tagged enum-variant payloads; non-inline value structs (always
  heap) and reference payloads are unaffected, and local bindings `auto x = f()`
  are not boxed.
