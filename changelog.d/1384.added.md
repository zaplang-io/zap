- **`repr` / `ascii` / `bin` / `oct` / `hex` built-ins** (PR#1384, decisions/lang/1384-repr-ascii-bin-oct-hex.md). The string-representation built-ins, all returning `str`. `repr(x)` is the debug form (strings quoted, `bytes` as `b'…'`, containers rendered with element `repr`, user types via `__repr__` / `@derive(Repr)`); `ascii(x)` is `repr` with every non-ASCII codepoint escaped (`\xNN` / `\uNNNN` / `\UNNNNNNNN`); `bin`/`oct`/`hex` render an integer in the Python sign-magnitude form with the `0b`/`0o`/`0x` prefix (`hex(255) == "0xff"`, `bin(-5) == "-0b101"`), over `int*` / `uint*` / `bigint`. Per the Python-exact dunder contract, `repr()` and container elements now prefer `__repr__` over `__str__` for a type defining both (str()/print() still prefer `__str__`).
