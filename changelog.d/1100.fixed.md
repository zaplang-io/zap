- **A struct (or any non-scalar) received from a typed `channel[T]` keeps its
  type** (I#1100, decisions/runtime/1100-channel-element-type.md). A value read
  with `<-ch` from a `channel[Entry]` used to come back as an opaque pointer
  (read back as `str`), so field access on it failed IR lowering with
  `error[ZAP6001]: field access on a non-struct value` even though the program
  type-checked. Channel elements are now classified through the same
  value-position path as list elements and dict values, so `channel[Struct]`,
  `channel[list[...]]` (and other nested collections), `channel[bytes]`,
  `channel[complex]`, and `channel[enum]` all round-trip with their real type on
  receive — field access, `len()`, indexing, and Display on the received value
  now work. Scalar `channel[int]` / `channel[float64]` are unchanged, and a
  tuple element (`channel[(T, U)]`) is still rejected cleanly (#703).
