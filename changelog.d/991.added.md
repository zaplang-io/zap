- **`net` — UDP datagram sockets** (I#991, epic #985,
  decisions/stdlib/991-udp-sockets.md). Connectionless `SOCK_DGRAM` sockets over
  the same opaque handle and netpoller as the TCP streams, matching Python's
  `socket` (`SOCK_DGRAM`) / Go's `net`. **Surface:** `net.udp_socket()` (IPv4) /
  `net.udp_socket6()` (IPv6) create an unbound datagram socket;
  `net.udp_bind(sock, host, port)` binds a local address (`port 0` → OS-assigned
  ephemeral, read back with `net.port`); `net.sendto(sock, data, host, port) ->
  int64` sends one datagram; `net.recvfrom(sock, n) -> (data, host, port)`
  receives one datagram with the numeric sender address; `net.udp_connect(sock,
  host, port)` records a default peer so the ordinary `net.send` / `net.recv`
  work on it (connected UDP). The shared `net.port`, `net.set_read_timeout`,
  `net.set_read_deadline`, `net.set_deadline_ns` and `net.close_conn` apply to a
  UDP socket unchanged. Divergences from Python (`docs/PYTHON_DIFFERENCES.md`):
  the datagram payload is `str` (as `net.recv`/`net.send` already are), not
  `bytes`; the address family is chosen explicitly at construction
  (`udp_socket` vs `udp_socket6`) rather than passed as an `AF_*` constant; a
  bind/send whose address family does not match the socket's raises. `net`
  remains Experimental.
