- **Associated functions on struct/enum types** (I#1260,
  decisions/lang/1260-associated-functions.md). A `def` inside a `struct` or
  `enum` body whose **first parameter is not `self`** is an *associated
  function*, callable as `Type.func(...)` — including through an import,
  `pkg.Type.func(...)` — and never on an instance. The canonical use is named /
  alternate constructors returning the declaring type (`Message.query(42)`,
  `Message.from_wire(data)`), alongside the field constructor `Message(...)` and
  instance methods (`m.to_wire()`). The call site is checked like a free
  function — arity, positional and keyword argument types, and `**kwargs` — and
  the function need not return the declaring type. There is **no
  `@staticmethod`/`@classmethod`**: Zap's receiver is explicit as `self` and the
  type name is statically known (no runtime class object), so the signature
  already distinguishes the two forms. New call-site diagnostics: ZAP4085
  (associated function called on an instance), ZAP4086 (instance method called
  without a receiver), ZAP4087 (unknown associated function). Associated
  functions on *generic* structs are a documented follow-up.
