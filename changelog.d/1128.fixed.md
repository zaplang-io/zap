- **Generic type-argument inference now reads a binary argument expression**
  (I#1128). The sibling of I#1117 (the unary arm): the inferer typed a bare
  integer literal `2` as `int64`, but typed *every* binary expression — the
  integer subtraction `2 - 5` included — as unknown. So `Optional.Some(2 - 5)`
  failed with `ZAP6001` ("cannot infer type argument 'T'"), and an untyped
  `auto count = 2 - 5` binding carried that unknown into every later use, so the
  issue's `Optional.Some(count)` failed the same way. A binary expression is now
  typed in the inferer, mirroring the language's binary result-type rules:
  arithmetic promotes through the numeric tower (`2 - 5` → `int64`, `2 + 1.0` →
  `float64`, `6 / 2` → `float64` by true division), `+` also concatenates two
  equal `str` / `bytes` / `list` operands, bitwise and shift operators yield
  `int64` (or `uint64` with an unsigned operand), and the comparison, logical,
  membership and identity operators yield `bool`. An operand the inferer still
  cannot type (such as a built-in call's result) leaves the expression
  unresolved, so a genuinely unconstrained parameter is still rejected.
