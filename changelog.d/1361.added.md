- **`datetime.resolve` gains a keyword-only `nanosecond=` fraction** (I#1361,
  decisions/stdlib/1361-resolve-fold-fraction.md). A named-zone wall clock can now
  be resolved with both an explicit DST `fold` and a sub-second fraction in one
  call — `datetime.resolve(ny, 2024, 11, 3, 1, 30, 0, fold=1, nanosecond=123456789)`
  keeps the fold-1 instant (EST, offset `-18000`) and all nine fractional digits;
  `fold=0` keeps EDT (`-14400`) with the same fraction. `nanosecond=` is
  keyword-only and defaults to `0`, so every existing `resolve` call is unchanged;
  `fold` keeps its keyword-or-8th-positional spelling. The fraction is stored
  verbatim (no range validation, matching `datetime.replace` and the lenient civil
  fields). `datetime.replace`'s documented default fold (`0`) is **unchanged** —
  the fraction was added to the civil-time constructor rather than changing
  `replace`'s contract. Unblocks the zaplang-io/datetime-utils#4 parser's
  repeated-wall-time handling (distinguishing the two occurrences via
  `zone_abbreviation` while retaining the fractional second).
