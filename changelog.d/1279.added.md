- **Exact scalar `min` / `max` built-ins** (I#1279,
  decisions/lang/1279-scalar-min-max.md; epic #1286). `min(a, b)` and
  `max(a, b)` return the lesser / greater of two numeric scalar arguments,
  Python-compatible in spelling. The result is the numeric join of the operands
  (two signed ints → `int64`, two unsigned → `uint64`, any float → `float64`),
  and for integer operands the comparison is an integer `icmp` + `select` that
  is **never routed through `f64`** — so adjacent `int64` values above 2^53 stay
  distinct (the DNS deadline use case, zaplang-io/dns#6). Equal operands return
  the first argument (Python tie semantics). Rejected with clear diagnostics:
  wrong arity (ZAP4025), any keyword argument (ZAP4023), a non-numeric or
  non-scalar operand (ZAP4024), and mixing a signed with an unsigned operand
  (ZAP4015). The variadic/iterable/`key=`/`default=` forms and `str`/`bigint`
  support are tracked as follow-ups in #1284.
