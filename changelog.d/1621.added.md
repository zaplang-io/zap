- **A handler adapted by a returning decorator can now declare an explicit typed
  context as its first parameter** (I#1621,
  decisions/lang/1621-context-adapter.md). The #1544 argparse seam generalizes
  from `fn(Namespace) -> R` to also admit one leading context parameter,
  `fn(C, Namespace) -> R`: the synthesized adapter takes `(C ctx, Namespace ns)`,
  forwards the dispatcher-supplied `ctx` to the handler's first parameter, and
  reads the remaining scalars from the namespace by name — matching the approved
  CLI contract (zaplang-io/cli#7, "a handler may declare `cli.Context ctx` as its
  first parameter; the dispatcher supplies it directly"). The context is the
  handler's first parameter and only the first; it is detected as the first
  parameter whose type is not an argv scalar, so no package type name is matched
  across the module boundary, and sema still checks the context type at the
  synthesized call. The context is optional on the handler — a `fn(C, Namespace)`
  seam also adapts a handler with no context, binding every parameter from the
  namespace. A plain `fn(Namespace)` seam is unchanged. Resolves the explicit-
  context deferral in the #1544 ADR. Unblocks zaplang-io/cli#4.
