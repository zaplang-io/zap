- **`datetime.resolve_imaginary` no longer changes the instant of a real
  `fold=1` datetime** (I#1173, decisions/stdlib/1149-named-zone-retention.md).
  On a fall-back overlap both `fold=0` and `fold=1` name real times one
  offset-step apart; `resolve_imaginary` used to snap the later (`fold=1`) value
  onto the earlier instant — the wall-clock fields stayed the same but the UTC
  offset and timestamp changed. It is now a strict no-op for any real wall clock
  (unique or ambiguous), preserving the value's own offset and instant, and still
  advances a genuinely imaginary (spring-forward gap) time across the transition.
  This matches the #1149 decision and the dateutil `resolve_imaginary` contract.
