- **Dereferencing a null built-in reference *value* now raises a located
  `NullReferenceError` instead of crashing** (I#1493 part A, Epic I#1489,
  decisions/lang/1489-null-reference-error.md). Extends the field read/store
  guarantee (PR#1511) to the reference *values* a program derefs: `len(n)`,
  `n[i]`, and `for x in n` on a null non-`Optional` `str` / `list` / `dict` /
  `set` / `bytes` / `deque` / `oset` / `heap` / `array` — e.g. the Epic's
  headline `len(n.name)` where the `str` field was left unset — previously
  SIGSEGV'd and now raise `NullReferenceError`, which `except NullReferenceError`
  and `except Exception` catch, with a located message (e.g. `null dereference
  taking the length of 'str' at foo.zap:7`, `indexing into 'list'`, `iterating
  over 'list'`). `Optional[T]` and non-null values are unchanged. A null
  user-struct receiver (`n.method()` / `n[i]` / `for x in n` dispatched through
  `__getitem__` / `__iter__`) is the remaining #1489 follow-up.
