# New decisions are per-file ADRs keyed to issue/PR number

**Status:** Locked

## Decision

Going forward, every locked decision is recorded as its **own file** under
`decisions/<domain>/<number>-<slug>.md`, not appended to the monolithic
[`DECISIONS.md`](../../DECISIONS.md). The decision's permanent identity is its
**governing GitHub issue number** (or PR number when there is no issue), replacing
the hand-allocated sequential `D-####` scheme. `DECISIONS.md` is frozen as the
historical record of `D-0001…D-0243`; see its header.

## Rationale

With more than a handful of concurrent PRs, the single `DECISIONS.md` file was a
hard bottleneck for two independent reasons:

- **Tail-append conflicts.** Almost every PR appended an entry to the file's end,
  so almost every pair of concurrent PRs produced a merge conflict there — pure
  friction, re-run after re-run of expensive CI on each rebase.
- **ID collisions.** The next `D-####` was allocated by hand. Two PRs open at the
  same time both read the same latest number and both claimed the next one; the
  collision could only be resolved by a human renumbering one of them, which then
  forced a rebase of everything stacked behind it.

One-file-per-decision removes the shared tail entirely (distinct filenames never
conflict). Keying identity to the issue/PR number removes hand-allocation: GitHub's
issue/PR number space is globally unique and monotonic, so two decisions authored
concurrently are guaranteed distinct keys with no coordination.

Alternatives rejected:

- **Keep `DECISIONS.md`, only fix IDs (assign at merge).** Still leaves the
  tail-append textual conflict, which is half the pain.
- **Mass-migrate the existing log into per-file ADRs now.** Would rewrite a
  10k-line file that a dozen open PRs currently append to, forcing every one of
  them to rebase and triggering a conflict storm — the opposite of the goal. We
  freeze instead and migrate nothing; the cutover moment for new entries is the
  maintainer's call once the open wave drains.

## Consequences

- New decisions go in `decisions/`; see [`README.md`](../README.md) for the
  format and [`TEMPLATE.md`](../TEMPLATE.md).
- [`INDEX.md`](../INDEX.md) is generated by
  [`scripts/gen-decisions-index.sh`](../../scripts/gen-decisions-index.sh) and
  checked by CI; it is never hand-edited.
- In-flight PRs that already added a `D-####` to `DECISIONS.md` are grandfathered.
- `DECISIONS.md` is never deleted; it remains the authority for `D-0001…D-0243`
  and for any superseding relationships recorded before the cutover.
