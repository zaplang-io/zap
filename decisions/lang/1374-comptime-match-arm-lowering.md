# Enum `@derive` runtime discrimination: the comptime match arm (#1374)

**Status:** Accepted — the engine/codegen slice of the enum-`@derive` epic
(#1371), implementing the surface decided in #1372 (Option C, `reflect.match`
with comptime-generated arms). Realizes it by **reusing the existing `match`**
rather than inventing discrimination codegen.

## Surface (refinement of #1372)

The generator writes an ordinary `match` whose arms are generated by a comptime
iteration over the type's variants:

```zap
match value:
    case comptime v in reflect.type_info(T).variants as payload:
        … comptime v.name …
        comptime for f in v.fields:
            … reflect.field(payload, comptime f.index) …
```

The single new arm form is `case comptime <loop_var> in <iter> [as <payload>]:`
— a `Pattern::ComptimeVariants`. This refines the #1372 sketch (which wrote a
`comptime for` *containing* `case`s): a `case` is not a statement, so a
`comptime for` cannot contain cases; folding the comptime loop into the `case`
header is the natural, parseable form, and no new `reflect.match` keyword is
needed — the existing `match` is reused directly.

## Lowering

Monomorphization expands the one comptime arm into **one ordinary variant arm
per variant** of the concrete enum (resolved from `reflect.type_info(T)` through
the active substitution, like the `comptime for` generator path):

- Each generated arm is a `Pattern::Struct { path: [Enum, Variant], args }`
  binding the variant's payload fields positionally to canonical captures
  `$cvp0, $cvp1, …` (a unit variant binds none). The arm is arm-local, so the
  fixed capture names never collide.
- The shared arm body is comptime-specialized per variant (binding `loop_var` to
  the variant's reflect record, so `comptime v.name` and the inner `comptime for
  f in v.fields:` resolve/unroll), and `reflect.field(payload, i)` rewrites to
  `$cvp{i}` — the i-th capture.
- The result is a plain `Stmt::Match` with ordinary variant patterns, lowered by
  the **existing enum-match codegen** (tag discrimination + payload field loads).
  No new runtime-discrimination lowering is added; the comptime arm never reaches
  sema's exhaustiveness check as itself (it is treated as covering every variant)
  nor the backend (mono expands it first; the lowering paths carry an
  internal-error guard).

A supporting change: the comptime specializer (`specialize_block`) now unrolls a
nested `comptime for` whose iterator is comptime-known in place, which is what
lets the arm's inner `comptime for f in v.fields:` unroll once `v` is a concrete
variant record (previously only a top-level `comptime for` was unrolled, by the
mono pass).

## Consequence

An enum `@derive` generator discriminates the active variant at runtime and reads
its payload, for tier-1 constant and tier-3 payload enums, with the discrimination
compiled as one exhaustive match (reusing the proven lowering). Exhaustive by
construction (one arm per variant). Regression-guarded by host tests
(`crates/driver/tests/zap_cli.rs`: the comptime match lowers to the expected
tag-dispatch + payload-load IR) and runtime goldens
(`tests/golden/enum_derive_sum.zap`, `enum_derive_tag.zap`) on the LLVM matrix.
Breadth across nested/recursive enums and a real codec is #1375.
