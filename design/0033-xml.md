## Abstract

AWS's XML wire protocols need a core `xml` module that can both read a response
body into a navigable tree and write a request body back out with **stable,
byte-deterministic** output (golden tests and request signing depend on it).
This note specifies a DOM parser + serializer: an element tree with tag name,
resolved namespace URI, attributes, child elements and text; navigation helpers;
XML entity (un)escaping; and deterministic serialization with default and
prefixed namespace declarations.

The module provides the XML **primitives**.
It deliberately does **not** know anything about AWS shapes — the aws-codegen
layer maps shape traits (`xmlAttribute`, `xmlFlattened`, `locationName`, wrapped
vs flattened lists/maps) onto these primitives.
This note shows, for each AWS feature the module must be able to *express*, which
primitive expresses it.

Out of scope (separate codec tickets — the `xml` module only carries text):
timestamp formatting, base64 blob decoding, percent-encoding.
A streaming pull-parser for huge S3 listings is a later follow-up; a DOM parser
is sufficient for v1.

## The DOM shape

The tree is two compiler-known prelude types (ship in `PRELUDE_SRC`, like
`JsonValue`), both **reference** structs so navigation returns shared nodes and
the builder methods mutate in place:

```
struct XmlAttr:
    str name       # attribute name as written (may be "xmlns", "xmlns:ns",
                   # "ns:attr" or a bare "attr")
    str value      # entity-decoded attribute value

struct XmlElement:
    str name                    # tag name as written — MAY carry a prefix ("ns:Foo")
    str namespace               # resolved namespace URI, "" if none
    str text                    # concatenated direct text content, entity-decoded
    list[XmlAttr] attrs         # attributes in document order (incl. xmlns decls)
    list[XmlElement] children   # child elements in document order
```

### Why this shape

- **A data model, not a fully general infoset.**
  Each element has a single `text` field (the concatenation of its direct text
  runs) *and* a list of child elements.
  This is the shape AWS protocols actually use: an element is either a leaf with
  text or a container with children.
  True **mixed content** (text interleaved *between* child elements, with order
  significant) is flattened — the interleaving order of text vs. elements is not
  preserved.
  This is the one documented v1 limitation; it never arises in AWS payloads and
  keeps navigation and deterministic serialization simple.

- **Lists for `attrs`/`children`, not dicts.**
  Document order is preserved and output is deterministic with no sorting pass —
  essential for signing canonicalization and golden tests.
  Lists also naturally carry **repeated siblings** (flattened lists) and
  **duplicate attributes**, which a dict would collapse.

- **`namespace` is the resolved URI, not the raw prefix.**
  Prefixes are scoped and inherited; a consumer wants the URI.
  Resolution is done once, during the parse, by threading the in-scope default
  namespace and prefix→URI bindings down the tree (see below).
  The raw, as-written `name` (prefix included) is kept so serialization round-
  trips and `local_name()` can strip the prefix on demand.

## Public API

Module functions:

| call | type | meaning |
|------|------|---------|
| `xml.parse(s)` | `str\|bytes -> XmlElement` | parse a document, return its root element |
| `xml.dumps(e)` | `XmlElement -> str` | serialize deterministically |
| `xml.element(name)` | `str -> XmlElement` | a fresh empty element (builder entry point) |

Navigation methods on `XmlElement` (read):

| method | type | meaning |
|--------|------|---------|
| `find(name)` | `str -> Optional[XmlElement]` | first child with that tag name |
| `find_all(name)` | `str -> list[XmlElement]` | **all** children with that tag name |
| `get_attr(name)` | `str -> Optional[str]` | attribute value by name |
| `get_text()` | `-> str` | the element's text content |
| `local_name()` | `-> str` | `name` with any `prefix:` stripped |

Builder methods on `XmlElement` (write; each returns `self` for chaining):

| method | type | meaning |
|--------|------|---------|
| `set_text(t)` | `str -> XmlElement` | set text content |
| `set_attr(name, value)` | `str, str -> XmlElement` | set/replace an attribute |
| `add_child(c)` | `XmlElement -> XmlElement` | append a child element |

Fields are public, so `e.name`, `e.namespace`, `e.text`, `e.attrs` and
`e.children` are read directly (e.g. `for c in e.children`).

## Expressing the AWS shape features

The module provides primitives; the codegen layer does the mapping. For each
required feature:

- **`locationName` (element/attribute rename).**
  The caller chooses the tag name: `xml.element("Renamed")`, or `set_attr` with
  the renamed attribute name.
  Parsing matches on the name the caller passes to `find`/`get_attr`.
  No special API — the DOM carries exactly the names given.

- **`xmlAttribute` (member-as-attribute).**
  Read with `get_attr(name)`; write with `set_attr(name, value)`.
  On serialize, attributes are emitted inside the start tag; on parse they land
  in `attrs`, distinct from child elements.

- **Wrapped lists/maps** (`<items><item>a</item><item>b</item></items>`).
  Build a wrapper element and `add_child` each member; navigate with
  `root.find("items")` then `items.find_all("item")`.

- **Flattened lists/maps** (repeated `<item>` siblings, no wrapper).
  `add_child` the repeated members directly onto the parent; navigate with
  `parent.find_all("item")`.
  `find_all` returning **every** matching sibling is what makes flattened lists
  work.

- **Namespaces.**
  A namespace declaration is just an attribute (`xmlns` or `xmlns:ns`); add it
  with `set_attr("xmlns", uri)`.
  Prefixed names are ordinary names containing a colon (`set_attr("ns:x", …)`,
  `xml.element("ns:Foo")`).
  On parse, `e.namespace` is the resolved URI; `local_name()` drops the prefix.

- **Navigable error documents.**
  Both AWS query/rest-xml error shapes are plain navigation:
  `root.find("Error").find("Code")` for the bare `<Error><Code>…` form, and
  `root.find("Error")` on an `<ErrorResponse>` root for the wrapper variant
  (where `root` is already the `ErrorResponse`).
  Because `.namespace` is inherited, `<Error>` under a namespaced
  `<ErrorResponse xmlns="…">` reports that URI.

## Parse

A two-layer design, mirroring `json` (D-0059):

1. **C pull-tokenizer** (`zaprt.c`): a flat, stateful cursor over the UTF-8
   source.
   `_lex_next` returns a token kind; `_lex_name`/`_lex_value` read the current
   token's name/value.
   Token kinds: `END(0)`, `OPEN(1)` (`<name`), `ATTR(2)`, `SCLOSE(3)` (`>`),
   `SELF(4)` (`/>`), `TEXT(5)`, `CLOSE(6)` (`</name>`), `ERR(-1)`.
   The tokenizer silently skips the XML declaration (`<?xml …?>`), processing
   instructions (`<?…?>`), comments (`<!-- … -->`) and `<!DOCTYPE …>`; it emits
   `<![CDATA[…]]>` as a literal `TEXT` token (no entity decoding).
   Entity unescaping for `TEXT` and `ATTR` values happens here:
   `&lt; &gt; &amp; &quot; &apos;` plus numeric `&#DD;` / `&#xHH;` (encoded to
   UTF-8); an unknown entity is passed through verbatim (lenient).

2. **Zap prelude builder** (`__xml_parse` / `__xml_build`): drives the cursor and
   assembles the tree with ordinary enum/list/dict operations, so the runtime
   never depends on the `XmlElement` layout.
   It threads the in-scope default namespace (`str`) and prefix→URI bindings
   (`dict[str, str]`, copied per element that declares a prefix) down the
   recursion, and resolves each element's `namespace` from its own + inherited
   declarations.

Keeping the C side a dumb, reusable tokenizer (no tree, no scope stack) is
deliberate: the later streaming pull-parser follow-up reuses it unchanged, and
namespace *policy* stays readable in Zap.

## Serialize

`xml.dumps` is a Zap prelude walker (`__xml_dump`) that appends fragments to a
`list[str]` and joins once (the `json.dumps` pattern), with C helpers for
escaping and the final concatenation:

- Children and attributes are emitted in list order → **deterministic**, no sort.
- An element with neither text nor children emits as self-closing `<name/>`.
- Text is emitted before children (irrelevant for AWS's non-mixed content).
- **Text escaping** (`xml._esc_text`): `&`→`&amp;`, `<`→`&lt;`, `>`→`&gt;`.
- **Attribute-value escaping** (`xml._esc_attr`): `&`→`&amp;`, `<`→`&lt;`,
  `"`→`&quot;` (values are always written in double quotes).
- Namespace declarations are ordinary attributes, so they serialize with no
  special handling — `xmlns`/`xmlns:ns` round-trip through `attrs`.

### Determinism contract

`dumps` is a pure function of the tree: same tree → identical bytes, every run,
under either GC collector.
The round-trip test asserts `dumps(parse(dumps(tree))) == dumps(tree)`, which
exercises parse/serialize symmetry without depending on insignificant input
whitespace.

## Module seam wiring (D-0056)

- `crates/syntax/src/parser.rs` — `XmlElement`/`XmlAttr` + the `__xml_*` prelude
  functions in `PRELUDE_SRC`; `"xml"`/`"XmlElement"`/`"XmlAttr"` added to the
  `references_prelude` needles.
- `crates/sema/src/modules/xml.rs` — type-checks `xml.parse`/`dumps`/`element`
  and the internal `xml._lex_*`/`_esc_*`/`_join` primitives.
- `crates/ir/src/lower/modules/xml.rs` — lowers `xml.parse`/`dumps`/`element` to
  the `__xml_*` prelude builders and the `_lex_*`/`_esc_*`/`_join` primitives to
  the `zap_xml_*` C runtime.
- `crates/codegen/src/modules/xml.rs` — declares the `zap_xml_*` runtime symbols.
- `crates/codegen/src/zaprt.c` — the C tokenizer + escaping/join helpers.

No grammar change (the module is a library, not syntax), so `docs/GRAMMAR.ebnf`
is untouched.

## Alternatives considered

- **Resolve namespaces in C with a scope stack.**
  Rejected: it forces the flat tokenizer to buffer whole start tags and manage
  push/pop lifetimes it otherwise never needs, for no gain on AWS-sized docs.

- **A single recursive `XmlNode` enum (`Element | Text`) for true mixed
  content.**
  Rejected for v1: mixed content never appears in AWS payloads, and the
  element+text data model makes navigation and determinism dramatically simpler.
  Can be revisited additively if a non-AWS consumer needs it.

- **`dict`-backed attributes/children.**
  Rejected: loses document order and repeated siblings, both of which AWS and
  signing require.
